已具备

  • 图片：180px 固定 tile + hover 徽标 + 文件名按钮
  • 灯箱：缩放 ±0.25、旋转、图集、下载、完整键盘
  • 视频：原生 video + 自绘悬浮栏 + HLS + 全屏
  • 音频：播放钮、语速、转写、下载

问题（按严重度）

  • 非图片附件无渲染：PDF / docx / zip 只落成一行文本

  • 三种媒体三种语言：图片裸缩略图、音频卡片、视频黑块
  • 视频控件缺项：无进度拖拽、无缓冲态、无音量
  • 无加载 / 失败态：artifactId 取流期间只有空白

方案 A · 自适应拼贴画廊

只改「网格容器」，缩略图尺寸与排列随图片数量决定，灯箱与文件名交互原样保留。

优化点

  • 1 张：16:10 大图 contain，不再被压成小方块
  • 2 张等宽 1:1；3 张 1 大 2 小；4 张 2×2；5–9 张 3 列
  • >9 张：前 8 张 + +N 遮罩入口
  • 统一右下角 i/n 计数胶囊
  • hover 操作条：下载 / 放大 / 更多

成本 / 风险

  • 成本：低，仅重写 UserAttachedImagesGallery 的容器与 tile 样式
  • 风险：须保持 ImageLightbox 的 index 映射逻辑不变
  • 不解决：文件卡片缺口、音频假波形
适用场景：图片是主要交付物（截图、设计稿、生图结果）。

方案 B · 统一媒体卡片

把「每种媒体各写一套」收敛为一个卡片骨架：媒体区（可选）+ 信息条。核心增量是补齐文件类型。

优化点

  • 图片 / 视频 / 音频共用同一容器、圆角、hover 行为
  • 信息条统一承载：类型图标、文件名、元数据（尺寸 / 大小 / 时长）
  • 新增文件卡片：PDF / xlsx / zip / 代码 都有图标 + 预览 / 下载
  • 音频去假波形，改为与视频一致的进度条
  • 操作按钮固定右下，符合扫视习惯

成本 / 风险

  • 成本：中，新增 MediaCard 组件 + 改造 3 处调用点
  • 风险：卡片固定 260px，窄屏需断点降级为单列
  • 依赖：PDF 内联预览仍需引入 pdf.js，短期只做「下载 + 跳转文件编辑器」
适用场景：产物形态多样（文件 / 图片 / 录屏混合），用户需要「一眼看清是什么文件」。

方案 C · 沉浸式聚焦

思路相反：不给每种媒体造卡片，而是让媒体「按重要性分配空间」——重点给大图，次要收成条。

优化点

  • 单图 contain 大图（限高 380），带左下角信息胶囊
  • 多图默认收成 72px 紧凑条 + +N
  • 音频去假波形；转写改时间轴分段，可点击跳转
  • 灯箱加缩略图条与键盘提示浮层
  • 建议补骨架屏与失败重试（取流期间当前为空白）

成本 / 风险

  • 成本：中高，涉及灯箱、音频播放器、消息渲染三处
  • 风险：紧凑条降低图片可见性，需要明确的产品判断
  • 收益：灯箱增强是纯增量，可单独先落地

融合方案：不需要选

A / B / C 解决的是三个不同层的问题，唯一冲突点是「图片要不要套卡片壳」，用一条规则就化解了。

一条规则

  • 图片 → 拼贴（图片本身就是内容，不加卡片壳）
  • 视频 / 音频 / 文件 → 卡片（需要元信息与控制）
  • 全部共享同一个增强灯箱
  • 音频禁止装饰波形，统一进度条
  • 操作按钮统一落在右下角

三期落地

  • P1：图片拼贴 + 文件卡片（互不阻塞，可并行）
  • P2：视频 / 音频收敛为媒体卡片
  • P3：灯箱缩略图条 + 键盘提示 + 加载/失败态
每期都能独立上线与回滚；P1-A 只涉及图集组件与其样式，是本方案里性价比最高的一步。

实施状态（2026-11-03）：P1-A 图片拼贴与 P3 灯箱增强已落地并通过 chat 目录 201 文件 / 2465 例测试。本页 D1 中的逐格计数胶囊与「⋯ 更多」按钮在实现时被裁决移除（前者属重复信息，后者无可打开的菜单），理由与偏离记录见 .agentdocs/workflow/261103-消息媒体渲染融合方案.md。文件卡片（P1-B）与音频去假波形（P2）尚未开工。

注：D1 里的图片与卡片分别来自方案 A 与方案 B 的真实实现，灯箱来自方案 C，三者共用同一套 token。

  1. 第一期（低风险）：方案 A 的自适应网格 —— 只动 UserAttachedImagesGallery，用户感知最强。
  2. 第二期（补能力缺口）：方案 B 的文件卡片 —— 解决 PDF / 表格 / 压缩包「零渲染」，预览先接已有 FilePreviewPane。
  3. 第三期（体验精修）：方案 C 的灯箱缩略图条 + 音频去假波形 —— 纯增量、可独立发布。

结论：推荐 ⑤ 融合方案

  • 三个方案的优点全部收进来，唯一冲突（图片要不要卡片壳）用「图片拼贴、非图片卡片」化解
  • 若只能先做一件事 → P1 图片拼贴：只动 1 个组件，感知最强
  • 若用户常收到文件 → P1 文件卡片：补的是能力缺口，不是美化
  • 想低风险尝鲜 → C 的灯箱缩略图条：纯增量，可独立发布

共同建议（无论选哪个）

  • 音频假波形应下线，它把装饰数据伪装成真实数据
  • 补媒体加载骨架与失败重试态
  • 浮层配色沿用 --bg-elevated + --fg-strong，禁用 --fg-on-accent（历史 bug 已验证）
顶部「切换亮色」可验证双主题表现 —— 媒体区在 Aurora Light 下的对比度是本次设计的重点验收项。
