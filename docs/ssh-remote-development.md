# SSH 远程开发使用与排错

## 终端

会话绑定 SSH 后，新建终端会在远程主机申请 PTY，默认目录取当前会话工作目录；子会话继承同一用户的父会话绑定。目录切换失败会结束终端，错误出现在输出中，避免命令意外在错误目录执行。连接断开时会报错，不会悄悄启动本机终端。

SSH 使用远端默认 Shell；本机 Shell 配置不能直接用于远程。初始化支持 POSIX、PowerShell 与 CMD 命令形式；CMD 目录中的变量扩展及控制字符被拒绝。Linux OpenSSH 有真实链路回归，Windows 命令构造有单测，Windows 实机验收需在对应环境执行。

终端断线后原进程/PTY 不会被重放。自动重连恢复连接后，需要重新创建终端；该行为避免重复执行历史输入。

## 连接与重连

- 同一个连接的并发请求复用一次握手。
- 活连接修改名称不重启；修改地址、用户或认证材料会关闭旧连接，之后重新连接。
- SSH keepalive 为 15 秒，连续 3 次无回应会由 ssh2 终止连接。
- 自动重连采用 1、2、4、8…秒退避，上限 60 秒。
- 手动断开、删除连接、主机密钥不匹配或凭证权限拒绝会暂停自动重连。
- 实际连接事件会同步写入持久化状态，连接列表不再保持过期的 connected。

## 主机指纹

采用按工作台用户、远端 host、port 隔离的首次信任（TOFU），指纹保存在 SQLite 的 ssh_known_hosts 表。第一次连接没有预置指纹，因此首次连接仍应在可信网络中进行。后续连接严格比对指纹；同一主机重新创建连接记录也不会绕过旧指纹。

服务器合法重装/更换主机密钥后，先通过可信渠道核对新的 SHA256 指纹。客户端提供：

```ts
await sshClient.trustHostKey(token, connectionId, {
  expectedFingerprint: 'SHA256:原有指纹',
  fingerprint: 'SHA256:已核实的新指纹',
});
```

此请求要求连接归属当前用户，使用旧指纹条件更新，关闭当前连接，随后由用户重新连接。不做自动接受密钥变更。该接口已封装在 @openAwork/web-client，未新增 UI 按钮。

## 凭证权限与备份

普通工作台用户使用自己上传/粘贴的私钥或密码。网关本地 privateKeyPath 和 SSH_AUTH_SOCK 对应操作系统账号的凭证，仅允许 ADMIN_EMAIL 指定的部署管理员使用，避免跨工作台账号借用。

新凭证以 enc.v2 格式加密，使用数据目录下随机生成的 ssh-credential-key.json（创建权限 0600），不再随 JWT_SECRET 轮换而失效。必须将此文件与数据库一起备份。首次升级时保持原 JWT_SECRET，系统会保存旧派生密钥以读取 enc.v1 凭证。首次升级之前就丢失/更换旧密钥的密文仍需重新输入凭证。

损坏密文或丢失密钥会明确报错，不再伪装成“未设置密码”。密钥文件包含敏感材料，不能提交到仓库或输出到日志。

## SSH 绑定调用迁移

`SSHClient.bind(token, connectionId, sessionId)` 的第三个参数现在必填。
旧两参数形式及 `placeholder:<connectionId>` 占位绑定已移除；调用方应先创建或选择
当前用户的真实会话，再传入返回的会话 ID。缺少 ID 时客户端直接报参数错误，
不发送请求；网关继续校验连接与会话的归属，不对占位 ID 放行。

## 目录与连接恢复

- 远程目录选择、会话 metadata 支持 POSIX 绝对路径、Windows 盘符路径与 UNC 路径。
- 创建目录按远程默认 Shell 选择 POSIX、PowerShell 或 CMD 命令；CMD 中含变量展开或控制字符的路径会明确拒绝。
- 终端创建前执行远程目录预检，目录不存在、无权限或超时会返回明确错误，不先创建一个立即退出的终端。
- SSH 解绑同步清理远程 metadata，并写入显式本地标记，防止重新继承父会话 SSH；重新绑定会同步恢复连接 ID。
- SSH 选择器遇到主机指纹冲突时展示旧、新指纹。用户通过可信渠道核验并勾选确认后才能更新和重连；冲突更新失败不自动重连。
- SSH 重连不会复活旧 Shell：旧终端保留退出状态，连接恢复后新建终端继续操作。
