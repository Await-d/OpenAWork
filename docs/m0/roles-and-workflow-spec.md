# M0 用户角色与交互流程定义 — 微信小程序点菜系统

> 版本：v1.0 | 日期：2026-06-22 | 状态：已完成

## 1. 项目概述

本小程序服务于两人协作点菜场景。用户 A 发起点菜并提交订单，用户 B 作为接单者收到通知并查看订单详情。

---

## 2. 用户角色定义

### 2.1 用户 A — 点餐者

| 属性         | 描述                                                                                     |
| ------------ | ---------------------------------------------------------------------------------------- |
| **角色标识** | `role_orderer`                                                                           |
| **核心目标** | 浏览菜单、选择菜品、提交点菜订单                                                         |
| **功能权限** | ✅ 浏览菜单列表；✅ 选择/取消菜品及数量；✅ 提交订单；✅ 查看订单确认页；✅ 查看历史订单 |
| **入口页面** | 菜单页（首页）                                                                           |
| **不可操作** | ❌ 接单/确认订单（B 的权限）                                                             |

### 2.2 用户 B — 接单者

| 属性         | 描述                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------ |
| **角色标识** | `role_receiver`                                                                            |
| **核心目标** | 接收点菜通知、查看订单详情、确认已接单                                                     |
| **功能权限** | ✅ 接收实时通知；✅ 查看订单详情（菜品列表、提交时间、备注）；✅ 确认接单；✅ 查看历史订单 |
| **入口页面** | 通知页/订单列表页                                                                          |
| **不可操作** | ❌ 修改菜品选择（A 的权限）                                                                |

### 2.3 用户关联方式

A 与 B 通过 **房间号/邀请码** 建立关联：

- A 创建房间，获得房间号
- B 输入房间号加入
- 同一房间内的 A、B 配对后，A 提交的订单自动通知 B

---

## 3. 核心交互流程

### 3.1 完整状态流转图

```
[待点餐] → [点餐中] → [已下单] → [已接单] → [已完成]
   ↑           |
   └───────────┘  (A 可随时修改选择)
```

### 3.2 状态定义

| 状态       | 英文标识    | 触发条件               | 所属页面                     | 描述                                       |
| ---------- | ----------- | ---------------------- | ---------------------------- | ------------------------------------------ |
| **待点餐** | `idle`      | A 进入菜单页           | 菜单页                       | A 尚未选择任何菜品，提交按钮禁用           |
| **点餐中** | `ordering`  | A 选择了至少 1 道菜    | 菜单页                       | 菜品已选择，提交按钮激活，A 可继续增减菜品 |
| **已下单** | `submitted` | A 点击"提交订单"       | 订单确认页（A）/ 通知页（B） | 订单已创建，B 收到实时通知，等待 B 接单    |
| **已接单** | `accepted`  | B 点击"确认接单"       | 订单详情页（A & B）          | B 已确认收到订单，双方可见接单状态         |
| **已完成** | `completed` | 手动标记或超时自动完成 | 历史订单页                   | 订单结束，归入历史记录                     |

## 4. 页面与功能映射

### 4.1 用户 A 的页面流

```
菜单页 → (选菜) → 订单确认页 → 提交 → 订单成功页
  │                                       │
  └─── 历史订单页 ←────────────────────────┘
```

| 页面           | 功能                                  | 关键交互                                   |
| -------------- | ------------------------------------- | ------------------------------------------ |
| **菜单页**     | 展示菜品列表，支持选择/取消、调整数量 | 未选菜品时提交按钮禁用；已选时显示数量角标 |
| **订单确认页** | 展示已选菜品摘要、总价、备注输入      | A 确认后提交，显示订单号                   |
| **订单成功页** | 提交成功提示，显示"等待 B 接单"状态   | 可查看实时接单状态更新                     |
| **历史订单页** | 列表展示历史订单，点击查看详情        | 按时间倒序                                 |

### 4.2 用户 B 的页面流

```
通知页 → (新订单通知) → 订单详情页 → 确认接单 → 已接单页
  │                                                    │
  └─── 历史订单页 ←────────────────────────────────────┘
```

| 页面           | 功能                             | 关键交互                       |
| -------------- | -------------------------------- | ------------------------------ |
| **通知页**     | 实时接收新订单通知，列表展示     | 新订单高亮显示，5 秒内出现通知 |
| **订单详情页** | 展示所有菜品、提交时间、A 的备注 | B 点击"确认接单"按钮           |
| **已接单页**   | 接单成功确认，显示双方状态       | 双方均可见"已接单"状态         |
| **历史订单页** | 列表展示历史接单记录             | 按时间倒序                     |

## 5. 通知机制

### 5.1 小程序内实时通知（核心）

- **技术方案**：微信云开发实时数据库监听
- **触发时机**：A 提交订单后，写入云数据库 `orders` 集合
- **B 端监听**：B 的页面通过 `db.collection('orders').where({roomId}).watch()` 监听变化
- **响应时间**：< 5 秒（实时数据库推送延迟）

### 5.2 微信订阅消息（可选增强）

- **触发时机**：订单提交时，调用微信订阅消息 API
- **前提条件**：B 需提前授权订阅消息
- **响应时间**：< 1 分钟
- **降级策略**：B 未授权时不影响核心流程，仅缺少跨应用通知

## 6. 验收标准

### US1：A 的点菜流程

| 编号   | 验收场景                 | 通过条件                                                        |
| ------ | ------------------------ | --------------------------------------------------------------- |
| AC-1-1 | 点菜成功时显示确认页面   | 提交后跳转至订单确认/成功页，展示订单摘要（菜品名、数量、总价） |
| AC-1-2 | 未选择菜品时提交按钮禁用 | 菜品数量为 0 时，提交按钮置灰不可点击                           |

### US2：B 的通知与接单流程

| 编号   | 验收场景                | 通过条件                                       |
| ------ | ----------------------- | ---------------------------------------------- |
| AC-2-1 | A 提交后 B 收到实时通知 | B 界面在 5 秒内出现新订单通知                  |
| AC-2-2 | B 查看订单详情          | 点击通知后跳转至详情页，展示所有菜品及提交时间 |

### US3：跨应用通知（可选增强）

| 编号   | 验收场景                 | 通过条件                                          |
| ------ | ------------------------ | ------------------------------------------------- |
| AC-3-1 | B 授权后收到微信服务通知 | A 提交点菜后，B 的微信服务通知在 1 分钟内收到消息 |
| AC-3-2 | B 未授权时降级           | 不影响核心流程，服务通知不收到消息                |
