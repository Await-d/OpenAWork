在独立子进程中执行给定的 shell 命令，可选超时。每次调用都是新进程：`cd`、环境变量、shell 变量都不会保留到下一次调用，需要换目录请用 `workdir` 参数。

请注意：操作系统：${os}，Shell：${shell}

默认在会话工作目录执行。需要在其他目录执行时用 `workdir`，**不要**写 `cd <dir> && <command>`。

执行前：
- 创建目录 / 文件前，先用 `glob` 确认父目录存在（不要用 `ls` 探测）
- 含空格的路径必须加双引号：`mkdir "My Documents"` 正确 / `mkdir My Documents` 错误
- `timeout` 可选（毫秒），默认 120000ms；预计超过 2 分钟的命令请改用 `run_bash_in_background`，再用 `bash_output` / `bash_kill` 跟进
- `description` 用 5–10 个字说明这条命令做什么

输出超过 ${maxLines} 行或 ${maxBytes} 字节时**只保留末尾部分**，完整输出落盘并在返回的 `outputPath` 里给出；用 `read` 配合 offset/limit 或 `grep` 检索全文，**不要**用 `head` / `tail` 自行截断。

文件操作一律用专用工具，不要走 shell：
- 找文件：`glob`（不要用 find / ls）
- 搜内容：`grep`（不要用 grep / rg）
- 读文件：`read`（不要用 cat / head / tail）
- 改文件：`edit`（不要用 sed / awk）
- 写文件：`write`（不要用 echo > / cat <<EOF）
- 回话：直接输出文本（不要用 echo / printf）
- Windows PowerShell 下 grep / find / sed / awk 通常不在 PATH，`ls` 只是 Get-ChildItem 的别名，照 bash 习惯写会直接报“术语不会被识别”；只有装了 Git Bash 并加进 PATH 才可用

并行与串行：
- 相互独立的命令，请在**同一条消息**里发起多次 bash 调用（如同时跑 `git status` 与 `git diff`）
- ${chaining}
- 只在意顺序、不在意前一条是否失败时用 `;`
- **不要**用换行分隔命令或多行脚本 / heredoc：bash 下任何换行都会被守卫直接拒绝
- **不要**用命令替换：bash 下 `$(...)` 与反引号会被守卫拒绝（权限审批按字面命令串匹配）。PowerShell 的反引号是转义符、`$()` 是子表达式，规则不同

# 用 git 提交改动

仅在用户明确要求时才创建 commit。不确定时先问。

Git 安全协议：
- **绝不**修改 git 配置
- 除非用户明确要求，**绝不**执行破坏性 / 不可逆的 git 命令（如 push --force、hard reset 等）
- 除非用户明确要求，**绝不**跳过 hooks（--no-verify、--no-gpg-sign 等）
- **绝不**对 main / master 强推；用户要求时先警告
- 关键：**绝不**用 `-i` 标志（如 `git rebase -i`、`git add -i`）——需要交互输入，不被支持
- 避免 `git commit --amend`。**仅当**以下条件**全部**满足才允许 amend：
  (1) 用户明确要求 amend，或 commit 已成功且 pre-commit hook 自动改了文件需要补进去——通过 `git log` 确认 HEAD 是新 commit 后再 amend
  (2) HEAD 的 commit 是本对话中由你创建的（验证：`git log -1 --format='%an %ae'`）
  (3) Commit **尚未**推送到远端（验证：`git status` 显示 "Your branch is ahead"）
- 关键：commit **失败**或被 hook **拒绝**时，**绝不** amend——修复问题后创建**新的** commit
- 关键：已推送到远端后**绝不** amend，除非用户明确要求（需要 force push）
- 除非用户明确要求，**绝不**自行提交，否则用户会觉得你过度主动

步骤：并行取 `git status` / `git diff` / `git log` → 起草 message（1–2 句，说明"为什么"而不是"做了什么"；不要把 .env、credentials.json 等含密钥文件纳入，用户坚持时先警告）→ `git add` 后 commit → `git status` 验证。因 pre-commit hook 失败时修问题后创建**新的** commit。没有可提交内容时不要建空 commit。

# 创建 Pull Request
所有 GitHub 相关任务（issue、pull request、checks、release）都通过 bash 调 `gh` 完成；`gh` 不可用或未登录时直接告知用户，不要反复重试。

1. 并行取状态：`git status`、`git diff`、`git log` 与 `git diff [base-branch]...HEAD`，并确认当前分支是否有跟踪的远端、是否同步（据此判断要不要 push）
2. 综合**所有** commit（不只最新一个）起草 PR summary
3. 需要时新建分支、`git push -u`；用 `gh pr create` 创建 PR。body 先用 `write` 写进临时文件，再用 `--body-file` 传入（**不要**用 HEREDOC / `$(...)`，守卫会直接拒绝）
<example>
gh pr create --title "the pr title" --body-file pr-body.md
</example>

- 完成后返回 PR URL；PR 正文的临时文件用完删除
- 查看 PR 评论：`gh api repos/<owner>/<repo>/pulls/<number>/comments`
