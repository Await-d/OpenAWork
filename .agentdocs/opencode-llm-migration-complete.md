## 技术债务

### 已识别的技术债务

1. **类型定义不统一** ⚠️
   - 部分模块使用 Zod schema，部分使用 Effect Schema
   - 建议：统一使用 Effect Schema

2. **错误类型系统** ⚠️
   - 当前使用 string tag，不够类型安全
   - 建议：使用 Effect Data.TaggedEnum

3. **测试工具混用** ⚠️
   - 单元测试和集成测试风格不一致
   - 建议：统一测试模式和辅助函数

4. **日志系统** ⚠️
   - 当前日志较为简陋

## Phase 6 cleanup audit update (2026-08-15)

本文件上方内容是 Phase 3.3 的历史快照，不代表本次续作已完成完整的 Effect 迁移。独立清理审查的当前结论如下：

- `@openAwork/opencode-llm` 包级 typecheck 已通过；迁移相关的包测试 65/65、gateway upstream/core 聚焦测试 53/53 通过。
- gateway 的生产 upstream/route 仍使用 AI SDK Promise/AsyncGenerator 边界：`runUpstreamGenerate` 调用 `generateText`，`runUpstreamStream` 使用 async generator，Fastify route 仍使用 `for await`。因此 T-42（移除所有旧 async/await）仍为 blocked。
- `services/agent-gateway/package.json` 中的 `ai` 与 `@ai-sdk/*` 仍被 `stream-runner.ts`、`run-upstream-generate.ts`、provider/cache 适配器和路由实际使用；没有证据支持删除，T-43 保持 blocked/not-applicable。`packages/opencode-llm` 本身未声明这些依赖。
- gateway 全量 typecheck 当前仍有 160 个 TypeScript diagnostics（Effect 4 bus/effect-bridge、消息/工具类型、route system 类型等），所以 T-44 不能宣称完成；详见续作结果文件。
- 由于上述兼容边界和类型阻塞，T-45 只完成证据审查，未进行 speculative refactor；T-46/T-47 的发布材料应明确标注“兼容路径 + 未完成项”，不应宣称生产发布就绪。
