## Task Overview

用户在视觉走查后反馈：对话主 tab 下「层级流动（flow）」与「历史层级（layered）」两个页面「内容展示不是很好」，并明确选定重构方向：

- 层级流动 → **泳道轨迹时间轴**（层为泳道、handoff 为跨泳道节点 + SVG 连线；打回/重试可见；活跃流动动画）
- 历史层级 → **追踪瀑布 Trace**（每层一条轨道，会话为时间条，打回连线；点条看完整对话；双栏/线程模式合并）

## Current Analysis（现状缺陷，已逐文件核对）

flow（`LayerFlowView` / `LayerFlowPipeline` / `LayerFlowTimelinePanel`）：

1. **"流动"是静态的**：`buildLayerEdges` 只取 `updatedAt` 最新一条 handoff，`buildLayerViews` 只取 `inbound[0]`；多轮往返、评审打回、重试全部不可见。
2. **活跃密度下箭头断裂**：`resolveVisibleEdge` 按 `FLOW_LAYERS` 绝对索引匹配，中间层被过滤后匹配不到边 → 显示"—"。
3. **信息重复**：顶部流水线与左下「层级交接记录」是同一份数据的两次排列，无增量信息；字号 8.5–11px 可读性弱。
4. `HandoffEntry.startedAt/endedAt/retryCount/failureReason/summary` 等字段基本未被消费。

layered（`LayeredConversationView` / `CrossLayerConversationView`）：

5. **"会话树"名不副实**：排序为 `depth → layer → time`，同父子节点不相邻，`│├└` 只表示缩进而非真实树。
6. **主线缺失**：看不出"任务经过哪几层、哪层卡多久、被打回过几次"；层级只剩头像色点 + route 徽章。
7. **详情上下文不一致**：双栏右侧是裸 `TeamConversationView`（无来源/去向/产物），线程模式才有一整套工作区；头部 3 行 chrome 挤压内容区。

共同根因：两页都是"列表化排列同源数据（handoff + layer node + session）"，**都没有时间轴**。

## Solution Design

统一视觉语法 =「泳道 × 时间」，一个强调现在时、一个强调完成时；复用同一套轨道/连线/时间轴 token。

### A. 层级流动 → 泳道轨迹时间轴

- 新模型 `layer-flow-swimlane-model.ts`（纯函数）：按 `updatedAt` 升序把 handoff 切成等宽列（列 = 时间槽）；`toRoleLayer` 决定节点所在泳道；`fromRoleLayer` 决定连线起点泳道。
- 连线起点列 = 源层在该 handoff 之前最后一次出现的列（无则 `col-1`），使打回/重试形成可见回折。
- 布局：左侧固定泳道标签列（图标/名称/状态/计数）+ 右侧横向滚动画布（HTML 绝对定位节点 + 覆盖层 SVG 贝塞尔连线）；活跃连线跑 dashoffset 动画；打开时自动滚到最右（最新）。
- 密度语义：`active` = 活跃 handoff ∪ 最近 8 条；`all` = 全部。
- 详情区保留既有 `LayerFlowDetailPane`（单层会话 / 跨层线程双模式不变）。
- 被替代并删除：`LayerFlowPipeline` / `LayerFlowNode` / `LayerFlowEdge` / `LayerFlowTimelinePanel` / `LayerFlowSessionGroupRow` / `LayerFlowHandoffEntryRow` / `layer-flow-timeline-model` / `layer-flow-timeline-row-styles`。
  `LayerNodeView` 类型迁入 `layer-flow-view-model.ts`（`LayerFlowDetailPane` / `LayerFlowRoleInstanceTabs` 改 import 源）。

### B. 历史层级 → 追踪瀑布 Trace

- 新模型 `layer-trace-model.ts`（纯函数）：复用 `buildLayerConversationRows` 的行，按层生成轨道；每条 bar 的 `[start,end]` 由该会话关联 handoffs 的 `startedAt/endedAt/updatedAt` 聚合（无 handoff 用 `timestampMs`）；全局时间范围做比例轴，范围退化时切换等宽轴；bar 宽度有最小可点宽度。
- 连线：`row.parentSessionId → bar` 派生（打回在图中向下回折）。
- 视觉：layer 色 + 状态色编码；`substate`（来自 layer node）作为阶段标记；活跃 bar 脉冲；选中 accent 描边。
- 交互：点击 bar → 下方详情区（`LayerDetailWorkspace` + `LayerSummarySidebar` + `LayerProcessPanel` + `TeamConversationView`，即原线程模式工作区），移除双栏/线程切换与左树。
- 层过滤 chips 语义改为"聚焦"：非匹配 bar 变暗而非隐藏，保持时间轴完整。
- `CrossLayerConversationView` 保留（仍被 `LayerFlowDetailPane` 的线程详情消费）。

### 约束

- 不新增后端调用；只消费 `useHandoffStore` / `useLayerStore` / runtime sessions / 既有 artifact hook。
- 新增样式集中到 `styles/team-runtime-layer-viz.css`（由 `team-runtime.css` @import），沿用 E · Nebula token 与 `team-conv-*` 命名。
- 单文件 ≤1500 行；渲染块 >80 行拆子组件；纯模型与组件同目录 + 单测。

## 第二轮优化（2026-09-16 用户反馈跟进）

反馈「层级流动不是很好」，自查发现三个客观缺陷，逐条修复：

### 缺陷与修复

1. **节点内容被裁切**：节点固定高 60px，而内容（路由行 + 两行摘要 + 状态脚 + 内边距 ≈ 73px）溢出被 `overflow: hidden` 裁掉 → 基准高度提升到 72px，并改为 `min-height` 渲染（长文本/长摘要撑高不再裁切，定位仍按基准高度居中）。
2. **连线"从虚空出发"**：起点取「上一时间槽的层中心」，不是真实来源位置 → 改为从**源会话在前序列的真实节点中心**出发：`SwimlaneNode` 新增 `fromSessionId`、`SwimlaneLink` 新增 `fromColumnIndex`（取源会话在目标列之前最近出现的一次）；找不到源节点（用户发起 / 源会话不在当前视图 / 仅更晚记录）才退化为左侧引入。链式交接因此逐跳相接，打回形成真正的回折。
3. **空间浪费**：详情面板常驻占 340–420px（未选中时也是空态占位）→ 改为按需展开：未选中时右栏不占位、轨迹画布吃满宽度；窄屏未选中时泳道同样占满高度。

### 新增能力

- **聚焦链**：`resolveSwimlaneFocusHandoffIds(model, selectedHandoffId)` 沿交接链（父 → 子）双向展开，选中一条交接即高亮整条链，链外节点/连线淡化（hover / 选中时恢复）。
- **横向滚轮**：滚轮纵向增量转横向滚动（原生监听 `{ passive: false }`），轨迹浏览不再需要 Shift + 滚轮。
- **工具条统计**：活跃 / 交接总数 / 时间跨度胶囊（复用 `formatTraceDuration`）。
- **尺寸调优**：列宽 136 → 128、节点宽 116 → 112、泳道标签列 148 → 132（与追踪瀑布标签列同宽，两个页面视觉语言统一）。

### 验证

- 泳道模型单测 **13/13**（新增源列解析 4 例、聚焦链 2 例、高度约束断言）；泳道视图 **4/4**（新增聚焦淡化用例）。

## 第三轮优化（2026-09-16 截图反馈）

用户给出实际运行截图，反馈「布局不好」。从截图定位到三个成因：

1. **右侧大片空白 / 内容集中在左侧**：画布宽度 = 列数 × 固定列宽（128px），当列数少（活跃模式 8 条）或屏很宽时，画布铺不满可视宽度 → 节点全挤在左边。
2. **时间刻度几乎无信息**：18 条交接集中在 13 分钟内，逐列显示同一个 `08:41`，时间轴失去"节奏"含义。
3. **节点信息偏小**：10px 摘要 + 9px 元信息在宽屏上难读。

### 修复

- **自适应列宽**：新增 `resolveSwimlaneColumnWidth(columnCount, viewportWidth)` —— 列少时按可视宽度平摊（上限 320px，列极少时不把节点甩得太远），列多时保留下限 144px 并横向滚动；列宽成为几何函数（`swimlaneColumnLeft/CenterX/NodeLeft`、`buildSwimlaneLinkPath`、`measureSwimlane`）的显式参数，节点定位随列宽居中。
- **相对时间刻度**：`formatSwimlaneTimeLabel(timeMs, firstTimeMs, previousTimeMs)` —— 与前一列同一小时内显示相对增量（`+12s` / `+3m`），否则回落绝对时间（同日 HH:MM、跨日 MM-DD）；跨分钟密集交接因此可读出"哪一跳拖了很久"。
- **尺寸与字号上调**：节点 112×72 → **120×76**，泳道高 92 → 96；路由 10→11px、摘要 10→11px（行高 1.45）、时间 9→10px、状态脚 9→10px；连线默认透明度 0.5 → 0.38（轨迹线是背景骨架，节点才是主体）。
- **共享测量 hook**：抽出 `use-element-width.ts`（ResizeObserver + window.resize 回退），由泳道画布与追踪瀑布共用（原瀑布内联实现移除）。

### 验证

- 泳道模型单测 **15/15**（新增自适应列宽 5 例、相对时间 1 例）。
- 泳道视图 4/4、追踪瀑布 7/7；**team 全量 130 文件 / 894 测试全通过**；`pages/team` / `stores/team` 域 `tsc` 0 错误。

## 第四轮优化（2026-09-16 第二张截图反馈）

截图暴露两个数据/布局一致性问题：

1. **内容与统计口径不一致**：画布显示"当前会话树内还没有跨层交接"，而泳道标签列与统计胶囊都显示有 1 条交接。
   根因：`isFlowHandoff` 只接受权威 5 层，`tester` / `user` 的交接被**静默丢弃**，而泳道计数走的是另一条聚合路径。
2. **泳道下方大片空白**：泳道高度写死 96px（5 层 = 510px），页面可用高度远大于此；同时无会话的泳道仍占整条高度。

### 修复

- **层归并而非丢弃**：`SwimlaneNode` 新增 `laneIndex`（`tester` → 评审泳道、`user` → 接待泳道），过滤改为 `isKnownLayer`（7 层全收）；`buildLanes` 与节点定位全部按 `laneIndex` 聚合 → 计数与画布口径一致，不再自相矛盾。
- **泳道布局改为累计度量**：新增 `resolveSwimlaneLaneMetrics(lanes, availableHeight)` / `resolveSwimlaneLaneCenters` / `swimlaneLaneTotalHeight`，取代等距的 `resolveSwimlaneLaneHeight`：
  - 空泳道（无会话且无交接）折叠为 **56px 窄条**（标签只留层名、弱化到 0.55）；
  - 剩余高度平摊给有内容的泳道，夹在 [96, 200] 之间；
  - 连线/节点 y 坐标改为查 `laneCenters`（`buildSwimlaneLinkPath(link, columnWidth, laneCenters)`）。
- **垂直居中**：泳道块 `margin: auto 0` + 外层容器改 `flex column`，内容不足时上下留白均衡（不再是"顶部对齐 + 下方空旷"）。
- 空态文案区分：`totalHandoffCount > 0` 而画布无列时提示"当前筛选下没有可显示的交接（共 N 条被「活跃」过滤）"。

### 验证

- 泳道模型单测 **19/19**（新增泳道度量 4 例、tester/user 归并不丢弃 1 例）；
- 泳道视图 6/6（新增筛选空态、tester 落泳道用例）；
- **team 全量 130 文件 / 900 测试全通过**；`pages/team` / `stores/team` 域 `tsc` 0 错误。
