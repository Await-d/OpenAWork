# 对话模式提示词收口（P0：优先级 / 回流 / 可执行模式公共纪律）

> **日期**：2026-09-23 ｜ **状态**：✅ 已完成（T-01…T-06 全部交付并验证） ｜ **范围**：`services/agent-gateway` 提示词与契约测试 + `.agentdocs`

## 1. 任务概览（Task Overview）

对 `clarify` / `coding` / `programmer` 三个对话模式提示词做三项收口（P0）：

1. **指令优先级**：所有模式声明裁决顺序，解决模式纪律与 AGENTS.md、子代理 / 类别提示词、工具章节的冲突无依据问题。
2. **模式回流**：为 coding / programmer 补「歧义时问清 / 方向性分歧建议切回澄清 / 方案失效先停再定」规则（现状只有 clarify → coding 单向流）。
3. **可执行模式公共纪律 + programmer 衔接**：抽取 coding / programmer 共用纪律片段（先读后写、事实驱动、最小变更、验证闭环、测试诚信），并将 agentdocs 落盘 / 登记 / 归档段从 coding 下沉为共用片段，程序员模式同样承接澄清方案（消除手动 clarify → programmer 的断链）。

## 2. 现状分析（Current Analysis）

- 三模式提示词是 TS 字符串数组，注入 `buildTwoPartSystemPrompts` 的 **stable 前缀第 7 槽**（`stream-model-round.ts:1272`）；模式与工具面按「本轮有效模式」收敛（`filterEnabledGatewayToolsForDialogueMode`）。
- 现有缺口：
  - coding / programmer 遇到需求歧义、需要用户多方案拍板时无行为约定（只能靠模型自行判断，可能与 yolo 偏好叠加成"默认推进"）。
  - 多来源提示词（AGENTS.md / 工作区规则 / 动态 agent 提示词 / 工具章节）同处 stable 段，无优先级声明。
  - agentdocs 计划衔接只写在 coding：用户手动 clarify → programmer 时计划不落盘、不登记、不归档，`/start-work`、boulder 发现链断。
  - coding 与 programmer 各自重复维护「先读后写 / 最小变更 / 验证闭环」等条目，存在漂移风险。
- programmer 的「禁止在不确定时给出未标注置信度的结论」不可执行（置信度无判定标准）。

## 3. 方案设计（Solution Design）

### 3.1 共享片段（SSOT，新增于 `stream-system-prompts.ts`）

| 常量 | 作用域 | 内容要点 |
| --- | --- | --- |
| `DIALOGUE_MODE_INSTRUCTION_PRIORITY_SYSTEM_PROMPT` | 三模式 | 项目约定 > 模式纪律 > 通用最佳实践；其他注入提示冲突时先说明再按优先级执行 |
| `EXECUTABLE_MODE_COMMON_DISCIPLINE_SYSTEM_PROMPT` | coding + programmer | 先读后写 / 事实驱动（附证据，推断标注假设）/ 最小变更 / 验证闭环 / 测试诚信 |
| `MODE_REFERRAL_SYSTEM_PROMPT` | coding + programmer | question 一次性问清；方向性分歧建议切回澄清；方案失效先停并给回退范围 |
| `AGENTDOCS_PLAN_HANDOFF_SYSTEM_PROMPT` | coding + programmer | 承接方案先落盘 `workflow/`，登记 `index.md`，同步勾选 `T-XX`，完成后归档 `done/` |

### 3.2 模式提示词调整

- **clarify**：仅接入【指令优先级】（只读约束、frontier 纪律、确认门控、agentdocs 输出规范保持原样）。
- **coding**：删除核心定位里的内联 agentdocs 长句与重复的【行为原则】四条目；改为接入三个共享片段 + 新增【快速路径】（求快不跳步、分批验证，替代原「一次一题」的串行语义）；【禁止事项】【工具使用策略】【多步任务策略】【输出风格】不变。
- **programmer**：接入三个共享片段；【行为原则】删除与公共纪律重复的「验证闭环」；【禁止事项】删除与公共纪律重复的「禁止绕过测试」，把不可执行的置信度条目改为「无法验证时必须标注"未验证"及证据缺口」。

### 3.3 契约测试扩展（`dialogue-mode-prompts.test.ts`）

- 三模式均包含【指令优先级】共享片段。
- coding / programmer 均包含公共纪律与模式回流片段（SSOT 引用同一常量字符串，防复制粘贴漂移）。
- programmer 与 coding 共用 agentdocs 衔接段（含 `.agentdocs/workflow/`、`index.md`、`T-XX`、`done/`）。
