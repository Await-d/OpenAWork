# 260924 · 工具展开可视化优化（Bash / 文件编辑 / 批量调用）

## Task Overview

优化三类工具卡「点击展开」后的可视化：Bash 命令（终端观感 + 执行中等待态）、
文件编辑 / 写入（内容变更直接可见）、批量调用（子行展开直接给内容）。
对齐参考实现 `temp/opencode-v2.0.15`（session-ui 的 shell / edit / write 渲染）。

## Current Analysis（改造前）

- 展开体没有「面板」：`.tool-call-block-body` / `.tool-call-batch-child-detail` 只有左竖线 + 缩进。
- Bash：展开态命令仍单行省略（多行命令被压成一行）；命令盒与输出盒是两个独立盒子；
  退出码 / 行数 / 错误行数散落两处；无执行中等待态。
- 文件编辑：`UnifiedCodeDiff chrome="minimal"` 透明底无边框；文件路径是单行 mono 文本；
  `参数` 抽屉默认展开，`old_string/new_string` 与 diff 内容重复。
- 批量调用：子行 chevron `display:none`；子行文字引用**未定义 token** `--text-1`；
  展开子行里嵌套卡重复 header，且需二次点击才能看到内容。

## Solution Design（最终落地）

1. **统一展开面板**：`--bg-overlay` 底 + `--border-subtle` 边 + 8px 圆角 + 12px 内边距 +
   2px accent 从属竖线；batch 子行用「引用块」形态（60% 叠加底 + accent 竖线）。
2. **Bash（对齐参考 shell 块）**：单终端面板 = 命令行（`$` + 完整多行 `pre-wrap` + cwd + 复制）
   → 输出区（stderr danger 左线 + stdout，max-height 288 滚动）→ 仅运行中显示 meta 行；
   移除 badge 汇总与「显示全部/较少」按钮；`running` 时显示「运行中，等待输出…」+ 闪烁光标；
   batch 子工具实时输出自动贴底。
3. **文件编辑（对齐参考文件卡）**：文件头 = 文件图标 + 目录（弱化、左侧截断）+ 文件名（强调）
   + `+N / -M`（成功/危险色）；diff 直接可见；`UnifiedCodeDiff` 新增 `hideHeader`；
   多文件各成一张文件卡；参数抽屉对 bash / diff 默认收起，embedded 下不渲染。
4. **批量调用**：子行 chevron 常驻可见（展开态旋转 + accent）；修 `--text-1` → `--fg-strong`；
   父卡运行中显示 4px 进度条（失败转 danger，终态移除）；子行展开以 `embedded` 渲染嵌套卡
   （隐藏自身 header，inline 卡隐藏整行且不展示入参）。
5. **默认展开**：`fileEdit` 类别默认展开（对齐参考的 locked-open 文件卡）；persist 版本
   7 → 8 一次性迁移；设置页类别列表常驻，全局开关关闭时仅 fileEdit 可单独关闭。

### 用户口径（2026-09-24 澄清，优先于历史描述）

- 核心是**可视化**：bash 要「实时终端执行」观感（含执行中等待）；编辑 / 写入直接看到内容变更；
  **入参 / 返回参不重要**。
- **单条 bash 的真·实时 stdout 本轮不做**：网关仅在 batch 子工具上转发 `onPartialOutput`
  （`stream.ts` 的 `sandbox.execute` 未传该回调）。本轮落地：终端面板 + 等待态 + batch 实时贴底；
  单条实时输出列为后续可选（需网关补事件）。

## 真·实时输出（单条 bash，用户明确要求「真实时」）

**背景**：网关此前只在 batch 子工具上转发 `onPartialOutput`（`tools/tool-sandbox.ts`
的 batch 路径），单条 bash 要等结算才有 output——终端卡在运行中只能显示等待态。

**落地（复用同一份数据契约，不新增协议）**：

- **网关**：新增 `routes/single-tool-live-output.ts` 的 `buildSingleToolPartialOutputWriter`——
  把滚动 stdout 写成 `tool_progress` 事件的**单元素 `subTools`**（`index: 0`、
  `status: 'running'`、`partialOutput`、`totalCount: 1`）。两个调用点接入：
  - `routes/stream.ts` 的 `executeToolCalls` 单条工具路径（`sandbox.execute` 的
    `onPartialOutput`）；
  - `routes/stream-runtime.ts` 的 `resumeApprovedPermissionRequest`（批准后执行被扣住的
    bash，同样实时推送；该路径无 WS/SSE，走 `publishSessionRunEvent`）。
  - 节流由 `tools/bash-tools.ts` 负责（80ms 窗口 + 尾包 + `MAX_OUTPUT_BYTES` 上限），
    网关侧不再二次缓冲。
- **前端**：`BlockToolCall` 读取 `input._batchProgress`（`applyStreamToolProgress` →
  `build-stream-assistant-trace` / `run-session-attach-effect` 注入，与 batch 子行同源），
  在 `isBashLike && output === undefined` 时把 `partialOutput` 合成为 live 视图
  （`mode: 'live'` + `running`），自动贴底；工具结算后 `_batchProgress` 消失，自动回到
  最终 output（不会与残留快照打架）。
- **复用件**：`buildPartialBashOutput` 下沉到 `tool-call/shared/partial-bash-output.ts`
  （batch 子行与单条 bash 共用，`tool-call/index.ts` 的公共导出保持不变）。

**验证**：网关单测 `src/__tests__/routes/single-tool-live-output.test.ts`（事件形状 2 例）；
web 单测新增「运行中渲染实时输出」与「结算后忽略残留 `_batchProgress`」2 例；
harness 新增 `bash-live` 用例（单条实时输出 + 自动贴底 + 不展示入参），**78 断言全绿**。

## 三次对齐：diff 语法高亮 + hunk 折叠（用户反馈「没有达到对齐的预期」）

**诊断**：参考实现的 diff 是 `@pierre/diffs`（语法高亮 + 行底色 + 「N 行未变更」折叠分隔），
我们此前是纯文本 diff——这是最后一块肉眼可见的差距。

**落地（不引 pierre，复用已在依赖树里的 `lowlight`/highlight.js）**：

- **`packages/shared-ui` 依赖**：新增 `lowlight`（运行时）+ `@types/hast`（dev）——
  两者本来就在 `bun.lock` 的传递依赖里（`rehype-highlight` → lowlight/highlight.js），
  **不新增实际下载、不引入第二份高亮实现**。
- **`UnifiedCodeDiff`**：
  - `highlightCodeLines(code, language)`：用 lowlight 的 hast 树整段高亮后按行拆 token
    （多行结构不丢），带 `hljs-*` 类名；超 80k 字符或语言未知时返回 undefined（退回纯文本）。
  - `detectLanguage(filePath)`：按扩展名映射（ts/tsx/js/jsx/py/go/rs/java/css/json/yaml/…）。
  - snapshot 路径（edit / write）按行号取 before/after 的高亮行；只有 patch 文本时
    退回逐行高亮（可接受降级）。
  - `toUnifiedDisplayRows` 把 hunk 头折算为「⋯ 第 N 行起 / ⋯ N 行未变更」分隔条
    （`parseUnifiedDiffRows` 保留原始 `@@ -a,b +c,d @@` 头以便计算）。
  - diff 容器恢复自带表面（0.5px 边框 + 72% `--bg-overlay` 底），与终端块同一层级语言。
- **主题**：hljs 语义色复用既有 token（`--hl-keyword/function/type/string/number/comment`），
  CSS 选择器扩为 `:is(.chat-markdown, .tool-call-block-diff)`，markdown 与 diff 共用一套映射。
- **验证**：shared-ui 180 测试（新增 hunk 分隔条 2 例、`highlightCodeLines` 3 例）；
  harness 新增 `patch` 用例 + edit 高亮断言，**96 断言全绿**。

## 六次对齐：目录类工具的可视化（list / 目录 read / 存储形态）

**发现的两个真实问题**（harness 探针先跑出来的）：

1. **刷新后的「存储形态」被降级**：存储层会把超过上限的工具输出序列化成 JSON **字符串**；
   前端 `ToolOutputPreview` 的领域提取器只认对象，于是 `list` 的目录树退化成一段 JSON 文本
   （harness 里 `list-dir-stored` 直接等不到 `.tool-call-tree`）。
   修法：`ToolOutputPreview` 入口统一做一次「看起来像 JSON 对象/数组」的字符串还原
   （`parseStoredJsonOutput`），所有领域预览（树 / 文件内容 / 诊断 / MCP …）一起受益。
2. **read 命中目录被当文件渲染**：网关对目录返回 `dir <名>` / `file <名>` 的文本清单
   （套 `applyLineWindow` 信封），UI 按「文件 N 行 + 行号代码」渲染，语义不对。
   修法：新增 `shared/directory-listing.ts` 的 `parseDirectoryListing`（单一判定处），
   `FileContentPreview` 走**目录清单**渲染（路径 + `N 项` + 目录/文件行，`data-directory-listing`），
   摘要 `formatReadRange` 对清单形态不带行区间。

**顺带修掉的 token 债**：`previews.css` / `shared.css` 里 12 处 `--text-1`（未定义，静默回退）
→ `--fg-strong`；`param-list-num` 的 `--brand`（未定义，整条声明被丢弃）→ `--hl-number` 混色。

**优化**：`list` 摘要带出路径与条目数（`已列举了目录 <path>（N 项）`），并像 bash/diff 一样
不再渲染参数区；目录树行的目录名颜色从 `--text-1` 回退值修正为 `--fg-strong`。

**验证**：web 定点 52 例（新增存储形态还原 3 例、list 摘要 2 例、目录 read 摘要 1 例）；
harness 新增 4 个用例 + 5 条断言，**150 断言全绿**。

**补记（同轮）**：`workspace_create_directory` / `workspace_review_revert` 也纳入同一口径——
`SuccessConfirmPreview` 不再透传英文工具名（改走 `naturalLanguageSummary` 的中文动作），
摘要带出路径；参数区对 `list` + 这两个工具统一隐藏（`HIDE_PARAMS_TOOLS`）。
harness 因此到 **159 断言**。
