## Solution Design

### 统一视觉规范（三处一致）

1. **页头**：`标题(18/700) + 单行说明(12/muted) + 右侧主操作`，独立成行，不套卡片。
2. **单层面板**：主内容用 `--bg-overlay` + `--border-subtle` + `radius-lg(12)`，**禁止**渐变 / 阴影 / 卡片套卡片 / `radius: 22`。
3. **紧凑列表行**：`10px 12px` 内边距，行分隔用 `--border-subtle`，hover 用 `--bg-raised`；行内存“主信息 + 状态徽章 + 操作”三段式。
4. **状态与操作**：状态统一 点 + 文本；行内操作默认低显、hover/focus 显形；危险操作走 complement 色；全部带 `:focus-visible` ring。
5. **冗余信息降级**：插件 Tool 名/参数、MCP 工具清单改为**默认折叠**（`<details>` / 展开行），不再平铺。
6. **统计信息内联**：KPI/统计卡改为页头内联文本（`市场 128 · 已安装 12 · 可更新 3`）。

### 信息架构调整

- **设置 → 插件**：左侧导航 240→200px，列表项只留「图标 + 名称 + 启用点」，描述移入右侧页头；右侧统一模板 = `页头（图标/名称/描述/主开关） + 插件配置区 + 工具摘要（折叠）`。
  - 图片插件 / 桌面控制 / 浏览器自动化：数据驱动 `PLUGIN_REGISTRY`，删除三份重复卡片 JSX。
  - 技能：复用共享 `use-installed-skills` + 新版 `InstalledSkillsManager`，删除重复数据逻辑（`SkillsPluginPanel` 变薄壳或删除）。
  - MCP：配置与运行状态**合并为单列表**（行 = 名称/ID + 来源徽章 + 状态点 + 工具数 + 开关 + 操作），编辑行内展开、新增用页脚按钮展开表单。
  - Web 搜索：删除 3 个 KPI 卡与路径卡，压成一行摘要 + 搜索 MCP 列表（复用 MCP 单列表）+ Provider 回退策略。
- **/skills**：删除 Hero 统计卡与「技能工作区」工具条；页头 = 标题 + 说明 + 内联统计 + 刷新；Tabs 与搜索/分类合并为一行粘性工具条；已安装视图改为单列紧凑列表，「注册源」收进折叠区。
- 不新增导航入口，不改路由。

## Complexity Assessment

- Atomic steps: ≥12（远超 5）→ +2
- Parallel streams: 3 条（技能线 / MCP 线 / 插件外壳线），但共享文件需串行协调 → +2
- Modules/systems: apps/web 设置页、apps/web 技能页、shared-ui、测试 mock → +1
- Single step >5min: 是（多处）→ +1
- Persisted review artifacts: 是（本文件 + runtime）→ +1
- OpenCode available → −1
- **Total score**: +6 → **Full orchestration**
- **Chosen mode**: Full orchestration / **Mode B（串行 in-context）**
- **Routing rationale**: UI 设计一致性要求高且三条线共用 shared-ui 组件与测试 mock，并行代理会产生
  设计漂移与文件冲突；由单一上下文串行实施、分阶段验证更稳（质量优先）。
