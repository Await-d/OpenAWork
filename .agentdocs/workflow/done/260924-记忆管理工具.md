# 260924-记忆管理工具（memory_manage）

## Task Overview

按 `mcp_manage_servers` 范式，为记忆域新增模型可见工具 `memory_manage`
（list / add / update / delete），让会话内模型在用户审批下维护用户级长期记忆。

## Current Analysis

- 现有入口：`routes/memories.ts` 的 `/memories`（list/create/get/update/delete/stats/
  extract/settings）；模型侧**无任何工具**。
- 数据模型（`packages/agent-core/src/memory/schema.ts`）：
  `type`（preference/fact/instruction/project_context/learned_pattern）、`key`（≤200）、
  `value`（≤4000）、`source`、`confidence`、`priority`、`workspaceRoot`、
  `teamWorkspaceId`、`roleLayers`、`enabled`。
- 写入安全：路由在 create/update 前对 `key`/`value` 跑 `scanMemoryWriteContent`
  （注入载荷 / Unicode 异常 / 超大内容），工具必须复用。
- 生效性：`buildMemoryBlockForSession(userId, metadataJson)` 在每轮流式请求时构建
  `<user-memory />` 块（`routes/stream-runtime.ts:361`）⇒ **写后下一轮即时生效**。
- 存储函数：`memory-store.ts` 的 `createMemory` / `updateMemory` / `deleteMemory` /
  `listMemories` / `getMemoryById` / `getMemoryStats`（update 为部分更新，支持 enabled 切换）。

## Solution Design

**工具**：`memory_manage`

```ts
{
  action: 'list' | 'add' | 'update' | 'delete',
  memoryId?: string,            // update / delete
  memory?: {                    // add 必填；update 部分字段
    type?: 'preference' | 'fact' | 'instruction' | 'project_context' | 'learned_pattern',
    key?: string, value?: string,
    priority?: number, confidence?: number,
    workspaceRoot?: string | null, roleLayers?: string[] | null,
    enabled?: boolean,          // update 可切换启用态
  },
  search?: string, type?: string, enabled?: boolean, limit?: number,  // list 过滤
}
```

- `list`：只读，返回 id/type/key/value（单条 value 截断 500 字符）/priority/enabled/
  source/updatedAt；默认 limit 50（上限 100）。
- `add`：`type + key + value` 必填；`source` 强制 `manual`（不接受模型伪造
  `auto_extracted`/`api`）；写入前跑安全扫描（key/value）。
- `update`：按 `memoryId` 部分更新；同样跑安全扫描（仅对传入字段）。
- `delete`：破坏性，审批预览展示目标记忆 key 摘要。
- 敏感/边界：不返回 `userId`；不写 `teamWorkspaceId`（v1 不支持团队知识记忆）。

**权限**：新类别 `memory_manage`（默认 ask）；`list` 经派生器返回 null 免审批；
变更动作 `scope=${action}:${memoryId ?? 'new'}`，`always=[${action}:*]`。

**会话守卫**：team / cron / channel 会话拒绝（记忆是用户级长期上下文，后台会话不得改写）；
可见性同步隐藏（team / cron / channel；clarify 自动排除）。

**提示词**：能力目录注入一行指引（与 MCP 提示合并为通用「管理类工具提示」）。

## 执行记录（2026-09-24）

- **唯一索引预检**：`memories` 表有 `(user_id, type, key) WHERE enabled = 1` 唯一索引；
  add/update 在写库前用 `findEnabledMemoryByTypeAndKey` 预检并给出可读冲突提示
  （避免把 SQLite 约束错误直接抛给模型）。
- **source 信任边界**：工具 schema 不接受 `source` 字段，落库强制 `manual`。
- **测试口径**：模块测试用真实内存 SQLite（`DATABASE_URL=:memory:` + migrate），

- **定向验证**：模块 14 例 + 沙箱 4 例 + 派生器（新增 3 例）+ 可见性（新增 2 例）

## 复查轮（2026-09-24，独立复审）

- **F1 [P2] 修**：`update {enabled:true}` 单独调用时唯一索引预检被跳过（原条件要求同时改
  type/key）→ 同键已有启用记忆时直接抛 SQLite `UNIQUE constraint failed`。修复：只要
  **结果态是启用**就预检；补回归（停用记忆重新启用撞键 → 可读错误且保持停用）。
- **F2 [P2] 修**：`add` 的 `enabled:false` 被静默忽略（模型以为记了停用记忆，实际是启用态）；
  且「先创建再停用」在存在同键启用记忆时必然撞唯一索引。修复：`CreateMemoryInput` 新增
  可选 `enabled`（agent-core）+ `createMemory` 落库时写入启用态 + 工具创建时直接写停用态；
  停用态创建跳过重复预检（不参与唯一索引）。补回归。
- **复审确认无问题**：归属校验（按 userId 过滤）、team/cron/channel 守卫、权限类别与
  deny-first 链路、`always` 的 category+scope 隔离、list 脱敏与截断。
- **复查后干净全量**：agent-gateway `test:unit` **576 文件通过 + 1 skipped /
  4491 用例通过 + 3 skipped，exit 0**（较复查前 +4 例 = 新增反例回归）。
- **过程偏差**：本域未单独创建 `.agentdocs/runtime/<task-id>/`（Full orchestration 默认要求），
  跟踪直接落在本 workflow 文档；因无 runtime 目录，归档时无需清理。后续域如需并行执行再补 runtime。

## Notes

- 安全扫描是硬门：工具内必须先扫描后写库（与路由同规），失败返回可读原因。
- `source` 强制 `manual`：防止模型把记忆伪装成自动抽取/API 写入（信任边界）。
- v1 不做：团队知识记忆（`teamWorkspaceId`）、记忆设置（settings 仍由设置页管理）、
  自动抽取触发（`/memories/extract` 保持人工/后台链路）。
