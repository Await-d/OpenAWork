# 260915-终端-vscode-能力对齐

## Task Overview

把聊天页内置终端从「能看能敲的管道 shell」升级为接近 VS Code 集成终端的核心体验，分三阶段：

1. **Phase 1 — 前端交互补齐**（xterm 插件、剪贴板、快捷键、输入合并）— 与后端解耦，可先行
2. **Phase 2 — 真 PTY 后端**（Bun 原生 Terminal API 替换 pipe stdio，resize/交互式程序/Ctrl+C 全对齐）
3. **Phase 3 — 传输与恢复增强**（增量流、完整 scrollback 恢复、端到端验收）— 可选收尾

目标入口：`QuickTerminalPanel`（底部抽屉）/ `SessionTerminalsPanel`（会话终端列表）中的 `InteractiveTerminalView`。

### 差距（对照 VS Code 集成终端）

1. **无真 PTY（核心差距）**
   - `persistent-terminals.ts:14-21` 明确注释 `intentionally not a real PTY`，`stdio: ['pipe','pipe','pipe']`。
   - 后果：vim/top/htop/less/ssh 密码交互等 `isatty` 程序失效；Ctrl+C 不产生正确 SIGINT；无作业控制。
   - `resizeTerminal` 为 no-op（`persistent-terminals.ts:291-299`），cols/rows 传不到进程，无 SIGWINCH。
2. **前端交互层缺失**
   - 依赖仅 `@xterm/xterm` + `@xterm/addon-fit`，无 search / web-links / unicode11 / canvas/webgl renderer。
   - 无剪贴板实现（全目录无 `clipboard` / `attachCustomKeyEventHandler`），无右键菜单、Ctrl+F 搜索、Ctrl+K 清屏。
3. **传输语义弱**
   - stdin：每次按键一个 HTTP POST `/stdin`（`InteractiveTerminalView.tsx:107-118`），长粘贴/连按会有延迟与请求风暴。
   - 输出：SSE 只带**累积快照的最后 8KB**（`TERMINAL_OUTPUT_TAIL_BYTES`），前端按字节差做 diff 回放（`InteractiveTerminalView.tsx:141-158`）；输出超过 tail 窗口时依赖「整段重写」，且**无 seq 保证**，极快输出会丢中间内容。
   - 刷新页面只能恢复最后 8KB，历史丢失。
4. **平台与运行时约束**
   - gateway 运行路径有三条：dev `tsx`（Node）、CLI `node dist/index.js`（Node）、桌面 sidecar `bun build --compile`（Bun，`services/agent-gateway/package.json:10`）。
   - Bun 原生 PTY **仅 POSIX（Linux/macOS）**，Windows 无官方支持。

## Solution Design

### 核心决策

- **D1 — PTY 采用 Bun 原生 `Terminal` API（Bun ≥ 1.3.5），不引入 node-pty / bun-pty**。`Bun.spawn(cmd, { terminal: { cols, rows, data(term, data) } })` + `proc.terminal.write/resize/close`。理由：零原生依赖、编译产物内建、与桌面 sidecar 构建链一致。
- **D2 — 后端抽象 `pty-backend`：能力探测优先 PTY，不可用则降级现有管道实现**。Bun 运行时（桌面 sidecar / bun 编译产物）→ 真 PTY；Node 运行时（dev tsx / CLI）与 Windows → 保持 pipe 路径，注册表契约不变。
- **D3 — 输出通道语义从「累积快照 + 字节 diff」升级为「增量字节流 + seq + 服务端 ring buffer」**。PTY 输出含转义序列，按 8KB 截断 + diff 会切断控制序列导致渲染错乱；改为增量事件并按序写入，重连时用 ring buffer 快照兜底。
- **D4 — 前端交互补齐直接使用 xterm 官方插件与 API**，不自造：`addon-search` / `addon-web-links` / `addon-unicode11` / canvas 或 webgl renderer；剪贴板走 `attachCustomKeyEventHandler` + `navigator.clipboard`。

### 已验证事实（2026-09-15 实测，本机）

- Bun **1.3.12**：`proc.terminal` 存在；`bash -i` 内 `isatty(0)=yes`；`resize(120,30)` 后 `tput cols=120`（SIGWINCH 生效）。
- **`bun build --compile` 产物同样全部通过**（独立二进制运行）→ 桌面 sidecar 主路径可行，无需第三方原生模块。
- 未覆盖：Windows 平台（Bun PTY 明确 POSIX only）、Tauri 真实打包环境（理论同编译二进制，风险低，列入 T-09 验证）、Node 路径降级（列入 T-10）。

## T-11 决策记录：stdin 传输通道（2026-09-15 收口）

**结论：维持 HTTP 批合并，不引入 WS 双向通道。**

**现状（T-03 已落地）**：`term.onData` → 16ms 合并窗口 + 单飞保序（同一时刻仅一个在飞请求，后续排队）+ 失败重排队（不丢字符）。因此请求数上界为 1000/16 ≈ **62.5 req/s**，且仅在用户持续输入时达到；真实打字（≤10 键/秒）下为个位数 req/s，粘贴为单次批量。

**关键实测核查**：
- `/sessions/:sid/terminals/:tid/stdin` **没有任何路由级限流**——网关的限流只覆盖登录（`infra/login-rate-limiter.ts`）、workspace 文件检索、team-phase-a force-apply。因此高频 stdin POST **不存在 429 风暴风险**，这是"HTTP 批合并足够"的决定性前提。
- 服务端 → 客户端方向已由 SSE 承担（增量 `seq` + ring buffer 回放）；再开 WS 会让「同一份输出」出现两条传输路径，违背单一事实来源。

**为什么 WS 不是默认路径**：
1. 延迟瓶颈是 **RTT**，不是请求开销。本地 sidecar / localhost 场景 RTT≈0，HTTP 与 WS 体感无差；远端高 RTT 场景两者同样受限（WS 省下的仅是 HTTP 头与连接复用成本）。
2. 引入 WS 需新增：WS 上的 JWT 鉴权、重连与重放、背压/信用窗口、与 SSE 的职责边界——成本显著高于收益。
3. 当前契约（`contract.md`）不涉及 WS；改动会同时波及网关、web-client、前端三条链路。

**重新评估的触发条件（满足任一才立项）**：
- 远端网关 + 高 RTT 下实测出现可感知输入回显延迟（>150ms）；
- stdin 请求量被实测证明成为服务端瓶颈（需先有指标，当前无证据）；
- 出现真实需求要做「终端级流控 / credit-based 背压」而非简单输入转发。

**残余项**：超大粘贴（MB 级）目前是单个 POST body，未分片。粘贴保护已在 >1000 字符时二次确认，实际风险低；若长粘贴成为真实工作流，再单独评估分片上传（独立于 WS 决策）。

### 测试用例清单（happy / 边界 / 失败路径）

| 层 | Happy path | 边界 | 失败路径 |
| --- | --- | --- | --- |
| PTY 探测 | Bun+非Win → `pty` | `bun+win32` / `node+linux` / `node+win32` → `pipe` + `reason` | 注入式纯函数不抛异常 |
| 进程后端 | 真实 spawn → `isatty` / resize | pipe 后端 resize 返回 `false` | 非法 cwd/shell 同步抛 → 友好错误（不 500） |
| 输出通道 | 增量拼接 == 全文；seq 单调 | >512KiB 丢头 + UTF-8 边界；非 live 返回 `null` | 累积快照变短 → 全量重发 |
| SSE | snapshot 首事件、output 次事件 | 竞态窗口事件恰好一次 | 订阅后 snapshot 写失败仍 teardown 订阅 |
| 输入队列 | 16ms 合并为 1 次请求 | 乱序响应（单飞）保持 FIFO | write reject → 回队首 + 上报 + 暂停重试 |
| 快捷键 | 各快捷键命中 | 无选中时不劫持复制；Alt 一律放行 | `Ctrl+C/D/Z` 放行给 xterm |
| 粘贴保护 | 小粘贴直通 | 阈值边界（1000 字符 / 5 行） | 取消确认则不发送；「不再提示」持久化 |
| 流回放 | 首次 snapshot reset + 写入 | 重连重发 snapshot 丢弃 | 旧后端无 `seq`/`data` → tail-diff 兼容 |
| 主题桥接 | 16 个映射 token 解析为 xterm 可吃格式 | `var()`/`color-mix()` → 跳过该键 | 变量缺失 → 省略键而非硬编码兜底 |
| 端到端 | 三视口布局无溢出 | 375px 浮层不重叠 | 断线重连历史不丢 + 状态提示 |
