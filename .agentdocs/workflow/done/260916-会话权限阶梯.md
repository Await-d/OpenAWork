# 260916-会话权限阶梯

> 归档说明：本方案已全部交付并验证，文档直接落位 `workflow/done/`；下方任务框为最终状态。
> Memory sync: completed（已并入 `index.md` 的架构决策与已知陷阱）。

## Task Overview

把会话级单一的布尔「YOLO」审批开关，替换为 **三档权限阶梯**：

| 档位 | 语义 |
| --- | --- |
| `ask`（默认） | 工具调用前先征求确认 |
| `auto-edit` | 仅文件 `edit` + `write` 类工具自动放行；shell / MCP / browser / 桌面控制等其余工具仍需确认 |
| `yolo`（legacy） | 跳过询问步骤；**显式 `deny` 规则始终优先** |

规范键为会话元数据里的 `permissionMode: 'ask' | 'auto-edit' | 'yolo'`；历史布尔 `yoloMode` 保留为**派生投影**（`yoloMode === (permissionMode === 'yolo')`），以兼容所有 legacy 读方与写方。

## Current Analysis

- 原实现只有布尔 `yoloMode`（开 / 关），无法表达「只自动放行文件编辑」这一最常用的中间档；用户要么全开要么全关。
- 权限判定是单点：网关 `tool-sandbox.ts` 的 `ensurePermissionForTool`。阶梯必须在此处落地才能成为真正的执行约束，而不能只是 UI 状态。
- 存在多条元数据写路径：Web 组合器、stream 请求级覆盖、会话 PATCH、子会话 / handoff 继承。若规范键与派生布尔各自为政，会出现「一端写了、另一端读不到」的静默漂移。
- 会话元数据 PATCH schema 为 `.strict()`，未知键直接报错 → 涉及**发布顺序约束**。

## Solution Design

1. **规范键 + 派生投影**：`permissionMode` 是唯一真相；`yoloMode` 由它派生回写，legacy 读写方零改动。解析统一走 `resolveSessionPermissionMode`（合法规范键优先，否则回退布尔）。
2. **写入侧 patch-aware 规范化**：`session-workspace-metadata.ts` 的 canonicalizer 采用 5 级优先级（patch 规范键 > patch 布尔 > 合并后规范键 > 合并后布尔 > 保持缺席），堵住 legacy 客户端写布尔被丢弃导致 session 卡在 YOLO 的**单向棘轮**。
3. **deny-first 不变量**：免审批快捷分支（`yolo` / 后台 team 会话）与 `auto-edit` 分支都在**通配符 allow/deny** 与**作用域级 allow/deny** 之后执行 → 中间 / 最高档只能跳过 `ask`，**绝不放行被显式 `deny` 的调用**。为此把 category 计算上提，使中间档能测试解析后的类别。
4. **继承有守卫**：task 子会话与 handoff 子会话仅在父会话**确实表达过档位**时才写入继承值，否则保持缺席。
5. **UI**：组合器为唯一写路径；顶栏降级为只读 chip（`yolo` 琥珀 / `auto-edit` 中性 / `ask` 不渲染）。

关键常量：`AUTO_EDIT_PERMISSION_CATEGORIES = {edit, write}`；`AUTO_EDIT_EXCLUDED_TOOLS = {workspace_review_revert}`（有意豁免：`patch` / `ast_grep_replace` 的删除与批量重写**属于**中档位覆盖范围，收紧靠显式 `deny`）。
