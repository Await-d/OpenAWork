# 260923-渠道入站图片与出站发图（Telegram / Discord）

## 任务概述

消息渠道审计（2026-09-23）发现两处高优先级缺口：

1. **入站图片**：除飞书外，Telegram / Discord 等平台收到图片消息时被直接丢弃（连占位符都没有）；
2. **出站图片**：只有飞书 / 微信 / QQ 能发图，Telegram / Discord 调用 `PluginSendImage` 直接抛错。

本任务为 **Telegram 与 Discord** 补齐「入站图片 → 多模态附件」与「出站发图 / 图片回复」。

**范围边界**：
- 不含 `sendFile`（需要先新增通用 `PluginSendFile` 工具，另立任务）；
- 不含语音 / 视频；不含 Slack / 企业微信 / WhatsApp（第二批）；
- 不改 `descriptors-*.ts`（两平台描述符已含 `PluginSendImage`）。

## 方案设计

### D-1 Telegram 入站图片（必须下载 → base64）

Telegram 文件 URL 需携带 bot token 才能访问，**不能**把 URL 交给模型，必须下载转 base64。

- parser 扩展：`photo` / `document(mime=image/*)` 消息在文本为空时也返回 `ChannelMessage`（`content='[User sent an image]'`）；
- 新增 `channels/telegram-media.ts`：`downloadTelegramInboundImage({ apiBase, message, signal })`
  - `photo` 取 `file_size` 最大项；`document` 要求 `mime_type` 以 `image/` 开头；
  - `getFile?file_id=` → `https://api.telegram.org/file/bot<token>/<file_path>` 下载；
  - **大小上限 4MB**（常量，超限跳过 + warn，保留占位符）——缓解 base64 入库膨胀；
  - mediaType 优先 `document.mime_type`，否则 `sniffImageMediaType`（`media/image-signature.ts:12`）；
  - 任何失败只 warn，不阻塞消息投递；
- `telegram.ts` 轮询：有 `text/photo/document` 即进入 parse → enrich → notify。

### D-2 Discord 入站图片（直接映射 URL，不下载）

Discord CDN 附件 URL 自带签名且可公开访问，且图片会立即进入处理队列，**不下载**以规避 base64 入库膨胀。

- parser 扩展（纯函数）：`attachments` 中 `content_type` 为 `image/*`（或扩展名兜底）的条目 → `ChannelImageAttachment{ imageUrl, mediaType, fileName }`；
- 数量上限 4 张（对齐工具输出图片上限口径）；
- 无文本但含图片 → `content='[User sent an image]'`；
- 非图片附件（zip 等）本次忽略。

### D-3 Telegram 出站图片

- `sendImage` → `POST /sendPhoto`（multipart：`chat_id` / `photo` / `caption?`）；
- `replyImage` → 同上 + `reply_to_message_id`（入参 `messageId` 形如 `chatId:msgId`，复用 `replyMessage` 的解析口径 `telegram.ts:219`）；
- caption 上限 1024 字符 → 截断（前 1021 + `…`），不追发全文（避免消息风暴，列为有意取舍）。

### D-4 Discord 出站图片

- `sendImage` / `replyImage` → `POST /channels/{id}/messages` multipart（`payload_json` + `files[0]`）；
- content 上限 2000 → 截断；
- 文件名 sanitize（Discord 拒绝特定字符）；
- `replyImage` → `payload_json.message_reference.message_id`。

### D-5 测试与验证

- 新增单测：`telegram-media.test.ts`（getFile / 下载 / 超限 / 失败降级）、出站 multipart 断言（Telegram `sendPhoto`、Discord `payload_json`+`files[0]`）；
- 扩展单测：`inbound-parsers.test.ts`（Discord attachments → images；纯附件不丢消息；Telegram photo → 占位符消息）；
- 回归：`telegram-poll-resilience.test.ts`、`auto-reply.test.ts`、`channel-tools.test.ts`、`feishu-*`；
- 命令：`bun run --filter @openAwork/agent-gateway test`、`bun run typecheck`、`bun run lint`、`bun run format:check`；
- 真实渠道冒烟（需 bot token）环境不可得时，按「环境阻塞 + 就绪步骤」记录。

## 风险与取舍

| 编号 | 风险 / 取舍 | 处置 |

| R-1 | Telegram base64 入库导致会话 DB 膨胀 | 4MB 上限 + 超限跳过 |

| R-6 | 非图片附件被忽略 | 保留原文本行为，不回归 |
