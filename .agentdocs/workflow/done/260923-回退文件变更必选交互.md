# 回退 / 重试的文件变更必选交互（三端）

## Task Overview

把「重试 / 编辑重发 / 回退」时的文件变更处理从**静默**改为**必选式交互**：

- 凡检测到受影响范围存在文件变更，操作前必须让用户明确选择（保留 / 恢复 / 取消，另加「打开文件变更面板」）；
- 无法自动恢复（无快照 / git 不可用 / 快照读取失败）时仍必须弹窗，不允许静默放行；
- 回退成功后给出可见反馈：Toast「已回退到所选消息」+「查看文件变更」入口；
- 覆盖 Web Chat、Team、移动端三端。

## Current Analysis（已核实事实）

| 缺口 | 现状 | 证据 |
| --- | --- | --- |
| 检测只依赖快照树 | 仅当受影响范围能查到 `snapshot_trees` 时弹窗；无快照/查询失败/无工作区 → 静默放行 | `useSnapshotAwareAction.ts:349-404` |
| 已有信号未用 | 消息 trace 的 `modifiedFilesSummary.files`（含 clientRequestId）与 `getRequestFileChanges` 按 request 投影均未被用作检测信号 | `useSnapshotAwareAction.ts:142-198`、`web-client/sessions.ts:604-609` |
| 回退后无反馈 | Chat 截断成功后无任何 toast / 标记 | `use-chat-retry-and-edit.ts:143-240` |
| Team 无提示 | `truncateAndResend` 只截断 + 重发 | `team-conversation-view-composer-actions.ts:148-187` |
| Mobile 无回退 | 长按「重新生成 / 重新发送」不截断、无提示 | `ChatScreen.tsx:390-484,732-782` |
| Toast 无 action | `toast()` 只支持 message/type/duration | `ToastNotification.tsx:5-18` |

## Solution Design

1. **检测三信号合并**（纯逻辑抽离，可单测）：
   - A 消息 trace：`readAssistantTracePayload` → `modifiedFilesSummary.files` + toolCalls 的 `clientRequestId`（零网络）；
   - B `snapshot_trees`（按 requestId，回退到时间过滤）→ 决定可恢复性 + 文件清单；
   - C `getRequestFileChanges`（按 requestId）→ 权威文件清单/统计；
   - `changesDetected = files > 0 || snapshots > 0`；无变更 → 静默继续（已确认口径）。
2. **对话框升级**（`SnapshotRestoreConfirmDialog`）：
   - 内联文件清单（滚动，最多 8 条 + 折叠计数）+ 摘要（N 文件 / +X -Y）；
   - 恢复不可用时展示原因，隐藏/禁用「恢复文件后继续」；
   - 新增「打开文件变更面板」（`onOpenFileChangesPanel` 可选注入）；
   - 保留既有：取消 / 保留文件并继续 / 恢复文件后继续（`restoreToTree` apply + deleteMissing）。
3. **Toast 支持 action**：`toast(message, type, duration, { action: { label, onClick } })`；带 action 时默认时长加长（8s），点击后 dismiss。
4. **回退成功反馈**：截断成功后 toast「已回退到所选消息」+「查看文件变更」（Chat）/「查看变更快照」（Team）。
5. **各端面板入口**：
   - Chat → 右栏审查面板（`setRightOpen + setRightTab('review') + setSidePanelActiveTab('review') + setReviewPanelOpened(true)` + revision 自增）；
   - Team → 本地 modal 承载 `SnapshotTimelinePanel`（team 可 import `components/chat/**`，不可 import `pages/chat-page/**`）；
   - Mobile → 不提供面板入口（无面板），文件清单在 Alert 后由消息列表体现；恢复走 `restoreToTree`。
6. **移动端行为修复（需明确批准）**：长按「重新生成 / 重新发送」改为**先截断再流式**（当前不截断会产生重复回答）；有变更时 Alert 三选（取消 / 保留并继续 / 恢复后继续），无变更直接执行。

## Complexity Assessment

- Atomic steps：≥5 → **+2**
- Parallel streams：Web/Team/Mobile 三流可并行 → **+2**
- Modules/systems：`components/chat/snapshot`、chat-page、team、mobile、toast → **+1**
- Long step（>5 min）：对话框改造 + 测试 → **+1**
- Persisted review artifacts：workflow doc → **+1**
- OpenCode available（Mode A）→ **−1**
- **Total score：6 → Full orchestration**
- **Routing rationale**：跨三端 + 共享核心 hook 改造 + 行为修复，失败半径大，需分阶段验证与状态同步。

## 复查轮次（2026-09-23，独立评审 + 修复）

独立评审（只读、按需求逐条核对）确认主流程正确，并发现 **7 项 P1 真实缺陷 + 若干 P2**。已全部处置：

### 已修复（P1）

| 编号 | 缺陷 | 修法 |
| --- | --- | --- |
| P1-1 | `detectionIncomplete` 是死标记：三路信号全失败且无 trace 时静默放行，与模块自身不变量冲突 | 检测不完整且无证据也弹窗（对话框新增 `detectionIncomplete` 态：「无法确认该消息之后是否存在变更」，隐藏恢复）；Web 与移动端同口径 |
| P1-2 | 快照 `created_at` 是 SQLite `datetime('now')`（UTC 空格格式），`Date.parse` 按**本地时区**解释 → 非 UTC 时区下受影响判定/恢复基线整体偏移 | `toTimestamp` 识别该格式并补 `Z` 按 UTC 解析（Web + 移动端）；新增 TZ 无关断言（`Date.UTC(...)`） |
| P1-3 | 排序末位兜底「按输入顺序取反」对 request-scoped（ASC）输入是反的 → 同秒 step 快照取到更晚者作基线 | `sortSnapshotsByCreatedAt` 增加显式 `inputOrder: 'asc' \| 'desc'`；调用点分别传 request-scoped ASC / session-scoped DESC；补同秒两组测试 |
| P1-4 | 移动端无并列兜底（DESC 输入稳定排序 → 同秒取最新） | 输入契约改为「按网关 DESC 传入」，内部翻转为 ASC 后稳定排序；补同秒测试 |
| P1-5 | 移动端 request 精确匹配零命中时不回退 → 与 Web 结论相反（静默） | 零命中回退到时间过滤 → 再退化为全部快照（与 Web 降级链一致）；补测试 |
| P1-6 | 移动端单个快照 detail 失败被静默吞掉，仍执行部分恢复并报成功 | 改 `Promise.allSettled`：任一 detail 失败即中止并提示「无法保证完整恢复」（与 Web 对齐） |
| P1-7 | `answer-retry` 用被删除的消息本身作检测源，其自身回合键被排除 | 收集改为 **inclusive**（Web + 移动端）：源消息自身回合键计入；补 assistant 源测试 |

- **P2-3** 放行分支收敛：新增 `finishWithoutDialog`，存在未决弹窗时先关闭并清空 pending，避免旧回调二次触发。
- **P2-4** 编排整体异常不再静默放行：按「检测不完整」弹窗（`DETECTION_FAILED_REASON`）。
- **P2-5** 移动端无凭据时 `truncateToMessage` 直接抛错（经 `runProceed` 提示），不再「跳过截断仍重发」。
- **P2-6** 恢复成功 toast 区分覆盖范围：展示过但不在快照文件集里的文件会计数，提示「另有 N 个文件未恢复」（不再笼统宣称已恢复）。

## Notes / 决策与风险

**已确认决策**（用户）：三端全做；不可恢复时给「保留 + 取消 + 打开面板」；回退后 Toast + 查看入口；仅检测到变更时弹。

**风险与缓解**：

1. 弹窗频率上升 → 已用「仅检测到变更时弹」口径；不做「记住选择」（会退回静默）。
2. 每次重试/编辑多 1–2 个网络请求 → 沿用 debounce(300ms) + generation 计数；请求失败且有 trace 变更时按「不可恢复」弹窗。
3. Team 面板入口是快照时间线 modal（无审查动作），与 Chat 的审查面板能力不同 → 对话框内联文件清单兜底。
4. 移动端「截断」是行为变更（修复重复回答），需明确批准后再实施。
5. Toast action 点击后必须 dismiss；duration 加长避免来不及点击。
