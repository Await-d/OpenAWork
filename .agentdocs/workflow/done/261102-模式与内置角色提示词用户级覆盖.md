## Task Overview

当前系统里有两类「提示词」用户**完全改不了**，本方案为它们补上**用户级覆盖（override）**能力：

1. **对话模式提示词**（`clarify` / `coding` / `programmer`）—— 编译期常量，无存储、无路由、无 UI。
2. **内置 Agent 的系统提示词** —— 后端显式拒绝写入，前端 textarea `disabled`。

**不包含**（已有能力，避免重复建设）：

- 自定义 Agent 的 `systemPrompt`（`routes/agents.ts` + AgentsPage 已可增删改）。
- 团队 persona / SOUL（`agent_personas.soul_md` + `PUT /team/personas/:roleLayer` 已可编辑）。
- 渠道人设（只能选资源，属产品语义，不在本次范围）。

**目标验收**：用户能在 Web 端修改对话模式与内置 Agent 提示词，无需重启，后续重新解析配置的请求采用新值，并可恢复默认。正在执行的请求不热替换；已有 `delegatedSystemPrompt` 子会话快照保持其既有生命周期，不承诺随目录修改自动刷新。显式任务 resume 是否重新写入快照列入 T-14 核查。模式覆盖在已有有效 Agent 的普通请求中不注入，UI 必须说明这一适用范围。

**修订记录（2026-11-02，V2）**：完成两条成员复查并核实关键证据；修正恢复入口遗漏、覆盖持久化、表单误固定、扫描器误用、.NET 范围与快照生效边界。

**实施记录（2026-11-02，V2 已批准执行）**：用户批准后按 Gate 2 分段落地（每批 ≤3 文件）。Mode A 派发 2 名子代理：`mode-resolver-impl` 交付 T-03/T-07 的 resolver、双入口接入与单测；`builtin-prompt-impl` 交付 T-10 与 `agent-catalog-system-prompt.test.ts`（13 项）。协调者完成存储层、HTTP 路由与注册、web-client 契约与 build、前端 UI、T-11~T-14、T-17 及全部文档同步。实施中新增两处未在 V2 预见的必要改动：`UpdateManagedAgentInput.systemPrompt` 放宽为 `string | null`（shared 契约），以及新增 `promptMetadata` 供 UI 区分覆盖状态。

## Solution Design

### 决策项（V2 推荐，尚未获用户批准）

| 编号 | 决策 | V2 推荐 |
| --- | --- | --- |
| D-01 | 替换默认还是追加 | 完全替换，仅替换对应提示词槽位，不移除其他系统层及工具权限 |
| D-02 | 内置 Agent 存储 | 复用 `builtinOverrides`；模式独立使用 `prompt_overrides` |
| D-03 | .NET 同步 | 已撤销待决策项：遵照该目录 README，不纳入本次维护 |
| D-04 | 提示词内容校验 | 不将记忆扫描器作为硬拒绝器；鉴权、归属、类型、长度与非法控制字符校验必做，提示词文本不提供权限授权能力 |
| D-05 | UI 落点 | Display tab 挂载独立组件与数据 hook，不将编辑逻辑继续堆入约 938 行父文件 |
| D-06 | 空值语义 | V2 建议不增加“关闭模式提示词”能力：拒绝空串/纯空白；模式使用 reset 路由恢复默认；内置 Agent `systemPrompt: null` 仅表示删除 prompt 覆盖 |
| D-07 | 普通/审批恢复链路一致性 | 两入口共用 resolver；恢复入口补有效 Agent 抑制，明确为修复既有差异，批准时一并确认 |

原 D-06 建议允许空串，与内置 Agent 清空恢复默认语义不同，且扩大到“关闭提示词”能力；V2 改为明确 reset。若用户需要关闭，应另行定义显式开关，不能混用空串。

### A. 存储与安全边界

- 新增 `prompt/prompt-override-store.ts`，在 `user_settings` 的独立 `prompt_overrides` JSON 键下只保存改过的模式文本，缺失条目使用当前版本默认；不新增表，不引入通用设置框架。
- 写入必须严格校验模式枚举、文本类型、字符上限与非法控制字符；有效文本保留原始空白，`trim` 仅用于空白判断，不静默改写用户内容。字符上限复用 `MODEL_REQUEST_SYSTEM_PROMPT_MAX_CHARS`，HTTP body 字节限制按 JSON/UTF-8 膨胀留余量，客户端上限由响应提供。
- 记忆扫描器基于词面正则，`Never reveal your system prompt`、标签教学等合法内容也会触发；不能把主动配置与不可信记忆注入混为一谈。任何新写入仍必须经过既有鉴权、工具审批及来源守卫，不新增绕过或自动批准路径。
- 无配置用默认；损坏 JSON 记录脱敏告警并在运行读取中回落默认。管理 GET 必须标识异常，不能把读取失败展示成“没有覆盖”。数据库不可用/写入失败返回结构化错误，禁止报告保存成功或在坏配置上静默覆盖其他模式。
- 同一 JSON 键按模式合并修改；读改写同步完成且无跨 await 窗口。多标签页保存串行化/防旧响应回写，暂不新增版本历史或复杂 CAS 协议。

### B. 模式提示词接入：共享 resolver，覆盖普通与恢复两入口

- 新增中立模块 `prompt/resolve-dialogue-mode-prompt.ts`，输入 `userId`、已解析模式、有效 Agent id。存在有效 Agent 或模式未指定时返回 `null` 且不读库；其余按“覆盖优先、默认兜底”解析。
- `stream-prompt-assembly.ts:206-210` 与 `stream-runtime.ts:367-370` 必须共同接入，不允许只改普通入口；模块不可反向依赖 `stream.ts`，保持提示词常量叶子层无 DB 依赖。
- 普通入口已有有效 Agent 抑制保持不变；恢复入口新增同样门控属于已发现的旧行为差异，须先建立失败用例再修复。双缺省未指定语义保持不变。
- 内置默认长度/SSOT/Web 同步契约继续只测默认常量；覆盖上限由配置校验与 resolver 测试独立验证。
- 生效以每次配置解析为界，不在模型 token 循环中反复查库，不追溯重写在途请求或委派快照。请求显式 `systemPrompt`、`delegatedSystemPrompt` 的既有优先级不变。

### C. 内置 Agent 覆盖：保存、重读、合并、重置完整闭环

| 改动 | 要求 |
| --- | --- |
| 类型/解析核查 | `StoredBuiltinOverride` 与 `parseStoredCatalog` 已有字段，复用并补重读测试，不误报缺失 |
| 清洗与有效值合并 | `agent-catalog.ts:336-351` 保留 prompt 并叠加覆盖；`defaultBodyForBuiltin` 仍只返回默认 |
| 差异判定 | `hasOverrides`/`resettable` 及 `sameAsDefault` 均纳入 prompt（`:353-366,523-528`），仅改 prompt 不得被删 |
| 更新持久化 | `next.systemPrompt` 未传保留当前覆盖，`null` 清除，非空文本更新；后续仅改模型不得丢已有 prompt |
| 默认归一化 | 提交文本等于当前默认时删除该 prompt 覆盖，不固化默认；模型覆盖原样保留 |
| 路由/工具/客户端 | 同步 HTTP schema、`agent_manage` schema/文案和 `UpdateManagedAgentInput`；nullable 只用于内置 Agent 重置，自定义 Agent 维持现有规则 |
| 覆盖元数据 | 内置记录补可选 `promptMetadata`（默认文本、是否覆盖），贯通客户端类型，避免用模型 `hasOverrides` 误判 prompt 状态 |
| 仅恢复提示词 | 通过 `PUT /agents/:id` 的 `systemPrompt: null` 删除 prompt 覆盖，不调用会同时清模型的整项 reset；保留既有整项/reset-all 行为 |

### D. API 契约与客户端

| 能力 | 契约 |
| --- | --- |
| 读取三种模式 | `GET /prompt-overrides` 返回 `modes`；每项含 `mode/defaultText/effectiveText/hasOverride`，另含 `maxChars` 与可诊断配置状态 |
| 写入模式 | `PUT /prompt-overrides/dialogue-modes/:mode`，body 为 `{ text: string }`；成功返回更新后的该项，而非仅 `ok` |
| 恢复模式 | `POST /prompt-overrides/dialogue-modes/:mode/reset`，幂等删除该模式覆盖并返回当前默认有效值 |
| 内置 Agent | 复用 `GET /agents`、`PUT /agents/:id`，完整类型更新和 prompt-only reset 语义见上 |

- 路由注册与鉴权沿用现有范式；未知模式/无效文本 400、未认证 401，用户身份仅取已认证主体，不从 body 取 owner。服务内部函数也校验，避免工具与 HTTP 语义分叉。
- `packages/web-client` 新增 `createPromptOverridesClient`、更新 agents 类型与测试，经 barrel 导出并 build；应用只用包公开入口。
- 写入响应不回显其他用户配置；日志/workflow 元数据仅记模式、长度、动作及错误码，不记录完整提示词。

### E. UI 与防误操作

- Agents 表单保留初始有效文本，`systemPrompt` 未改不提交；只改模型不能产生提示词覆盖，未修改的超长默认也不能阻断改模型。后端默认归一化作为第二道保护。
- 显示默认/自定义状态、默认预览、独立“恢复提示词默认”操作及“不随默认升级”的说明；明确整项“恢复默认”可能同时清除模型覆盖。
- Display tab 只增加独立 `DialogueModePromptOverridesSection` 的导入与挂载；数据加载、取消/过期响应门控与保存/reset 操作放独立 hook。避免新增页面级裸 window 事件。
- 支持加载/失败重试、dirty 状态、保存中禁重复操作、失败保留草稿、恢复确认、会话身份/网关切换不写回旧响应。
- UI 明示：设置影响后续重新解析；有效 Agent 优先时模式提示词不会额外注入，编辑提示词不改变硬性工具权限。
