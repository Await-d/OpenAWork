# 260924-MCP 自助管理工具（让产品内 Agent 能添加/修改 MCP）

## Task Overview

当前 MCP 只能通过设置界面 / 直接调 `PUT /settings/mcp-servers` / 改库添加，模型侧只有
`mcp_list_tools`、`mcp_call`、`skill_mcp` 三个「使用」类工具。本任务新增一个网关工具
`mcp_manage_servers`，让会话内的模型可以在**用户审批**下自助添加、修改、启停、移除
MCP 服务器配置，并立即生效（下一轮即可看到扁平 MCP 工具）。

## Current Analysis

现状事实（已核实）：

- 模型可见工具清单：`services/agent-gateway/src/tools/tool-definitions.ts:151`
  `MODEL_VISIBLE_GATEWAY_TOOLS`；MCP 相关只有 list/call/skill_mcp。
- 配置真相源：SQLite `user_settings(user_id, key='mcp_servers')`，由
  `mcp-runtime.ts` 的 `loadConfiguredMcpServersForUser` 每次调用时读取（无缓存），
  与内置 MCP（`builtin-mcps.ts`）合并；连接池 key 含配置指纹，改配置即失效。
- 写入校验：`mcp-settings-schemas.ts` 的 `mcpServerConfigSchema` /
  `mcpServersBodySchema` / `sanitizePersistedMcpServers`；virtual/adapter 内置
  （codegraph/git_bash/lsp/omo）端点受保护，只接受 enabled/disabledTools。
- 权限主链：`tool-sandbox.ts:6029 ensurePermissionForTool`；类别来自
  `@openAwork/agent-core` 的 `TOOL_TO_PERMISSION_CATEGORY`；未映射 → `custom`(ask)；
  `ALLOW_BY_DEFAULT_TOOL_NAMES` 是唯一的「工具级 allow」清单。
- 免审批分支（deny 之后）：`yolo`、team 后台成员、cron 的 `task_run`、reception
  只读、渠道会话 `channel-policy`。**team 后台会话无法交互审批**，若新工具落在这里
  会被静默自动放行 → 必须在会话层显式拒绝。
- 工具可见性：`session-tool-visibility.ts` 的 `isGatewayToolEnabledForSessionMetadata`；
  渠道会话按 `channelToolAllowlist`/`channel.tools` 过滤（新工具默认不可见），
  clarify 模式按只读白名单过滤（新工具默认不可见），team 会话当前无差别放行。
- 静态白名单：`tool-sandbox.ts:514 TOOL_WHITELIST`；不变量测试
  `tool-sandbox-allow-by-default-guard.test.ts` 要求白名单工具必须已分类。
- 写库后刷新连接：`retryMcpConnectionForUser(userId, serverId)`（探活 + 刷新
  catalog 快照 + 返回工具数/错误），settings 路由的 retry 已用它。

## Solution Design

### 工具契约（单工具 + action 枚举）

`mcp_manage_servers`：

```ts
{
  action: 'list' | 'add' | 'update' | 'remove' | 'enable' | 'disable',
  server?: { id?, name, transport: 'sse' | 'stdio', url?, command?, args?, cwd?,
             env?, headers?, required?, disabledTools?, oauth? },  // add/update 必填
  serverId?: string,   // update/remove/enable/disable 必填
  enabled?: boolean,   // update 可选
}
```

- `list`：返回合并后的全部 server（含禁用项）的**安全字段**
  `{ id, name, transport, enabled, builtin, source, disabledToolsCount }`——
  **绝不返回** url / command / env / headers（防密钥回显）。
- `add` / `update`：同一条读-改-写路径（同 id 覆盖）；`id` 缺省由 name 派生 slug。
  校验复用 `mcpServerConfigSchema`；**拒绝**把 system builtin（websearch/grep_app）
  当作自定义端点覆盖（只能启停/禁用工具），protected virtual/adapter 走管理条目。
- `remove`：删除用户配置条目；同 id 为内置时语义 = 恢复内置默认（结果里注明）。
- `enable` / `disable`：对用户条目、system builtin（写完整内置端点 + `source:'user'`，
  对齐 UI 语义）、protected builtin（管理条目 `source:'system'`）分别构造持久化行。
- 写库后立即 `retryMcpConnectionForUser` 探活，把 `{ status, toolCount, error? }`
  带回给模型（失败不算工具失败，配置已保存）。
- 只写当前会话 owner 的 `user_settings`；工具不接受 userId 参数。

### 会话守卫（执行前，fail-closed）

读 `sessions` 行（metadata_json / role_layer / team_parent_session_id / handoff_state）：

- team 会话（role_layer 为 team 角色或 team_parent_session_id 非空）→ 拒绝；
- `metadata.source === 'cron'` → 拒绝（无人审批）；
- `metadata.source === 'channel'` → 拒绝（防御；可见性层已默认隐藏）。

其余会话走正常权限门控（ask；yolo 免审批属用户显式授权，接受）。

### 权限

- agent-core `PERMISSION_CATEGORIES` 新增 `mcp_manage`（label「MCP 管理」，
  defaultAction `ask`，supportsPatterns true）。
- `TOOL_TO_PERMISSION_CATEGORY` 映射 `mcp_manage_servers → mcp_manage`。
- **不**加入 `ALLOW_BY_DEFAULT_TOOL_NAMES`。
- 权限派生器：`action === 'list'` 返回 `null`（只读免审批）；变更类返回
  `{ scope: serverId || 'new', riskLevel: 'high', previewAction, always: ['*'] }`，
  审批预览显式展示 transport + 目标（sse 显示 url 主机；stdio 显示完整 command+args）。

### 可见性

- `MODEL_VISIBLE_GATEWAY_TOOLS` 注册 + `TOOL_WHITELIST` 登记（guard 测试要求分类）。
- `session-tool-visibility.ts` 显式隐藏：team 会话（`teamWorkspaceId` /
  `teamRoleInstance`）与 `source === 'cron'` 返回 false；渠道/clarify 自动排除。

### 提示词

`stream-system-prompts.ts` 的 MCP 策略段落补最小一句：需要新增/修改 MCP 时使用
`mcp_manage_servers`，变更类操作需用户批准。

## Notes

- **安全边界**：stdio 等价本地命令执行（与 bash 同级），依赖 ask 审批 + 预览；
  不提供任何绕过权限的路径；deny 规则始终优先。
- **不做（v1）**：OAuth 交互式授权自动化（只写配置并提示需浏览器完成）；
  模型覆盖 system builtin 端点；team/cron 会话管理；MCP marketplace 安装。
- **风险**：`always: ['*']` 的永久允许会覆盖整个 `mcp_manage` 类别（与 write 等一致），
  审批文案必须写明「所有 MCP 管理操作」。
- **回归面**：permission-categories 新增项会进入 DEFAULT_PERMISSION_RULES 与设置页类别列表
  （自动派生，需确认前端无枚举假设）；tool-definitions 新增工具会进入所有非渠道会话的
  工具清单（token 成本 +1 工具，可接受）。
