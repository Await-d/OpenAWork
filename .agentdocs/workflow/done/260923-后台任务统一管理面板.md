# 260923-后台任务统一管理面板

## 任务概览

系统已有成对的后台工具（`run_in_background` 子代理 ↔ `background_output` / `background_cancel`；`run_bash_in_background` ↔ `bash_output` / `bash_kill`），前端也各有展示面，但**分散在三处**（时间线卡片 / 对话左轨+输入框上方 / 右栏「终端管理」+「代理详情」），缺少：

1. 一处能**同时看完**当前会话所有后台对象（子代理任务 + 后台命令）的统一视图；
2. 统一的**停止/终止**入口（现在子代理走左轨、后台命令要切到终端 tab）；
3. `task_id`（模型侧主键）在 UI 上不显眼，用户手工对照困难。

本方案交付一个**右栏「后台」面板**：聚合展示 + 统一操作。**v1 不改网关、不加接口**。

## 现状分析（已查证）

### 后台能力与前端对应关系

| 对象 | 启动 | 查看 | 取消/终止（模型侧） | 前端管理入口 |
| --- | --- | --- | --- | --- |
| 子代理任务 | `task` / `Agent`（`run_in_background=true`） | `background_output` | `background_cancel`（单个 / `all=true`） | 对话左轨 `SubAgentRunList`（逐行停止）、输入框上方 `BatchStopSubAgentsControl`（全停+确认）、右栏「代理」tab `SubSessionDetailPanel` |
| 后台命令 | `run_bash_in_background`（返回 `terminalId`） | `bash_output` | `bash_kill`（SIGTERM→3s SIGKILL） | 右栏「终端管理」tab：真终止 / 清屏 / 重命名 / 分屏；底部 `TerminalCollapsedRail` |
| 交互式 PTY | `interactive_bash` | 终端面板 | 终端面板终止 | 同上（`kind='foreground'` 才可输入/清屏） |

### 数据源（v1 全部复用，无需新接口）

- **子代理任务**：`SessionTask`（`packages/web-client/src/session/sessions.ts:430`）——含 `id`(=`T-…`)、`title`、`status(pending|running|completed|failed|cancelled)`、`assignedAgent`、`sessionId`、`createdAt/startedAt/completedAt`、`result/errorMessage/terminalReason/timeoutSource`、`blockedBy`、`metadata`。来源：`recovery.tasks` + `getStatus`（3s 轮询，`shouldPollSessionSubresources`）+ 流内 `task_update` 事件（`applySessionRuntimeEvent`）。
- **后台命令**：`SessionTerminalSummary`（`packages/shared/src/index.ts:1473`）——含 `terminalId`、`kind('foreground'|'background'|'tmux')`、`toolName`、`command`、`description/name`、`cwd`、`status`、`exitCode`、`startedAtMs/endedAtMs`、`outputBytesTotal`、`outputTail`。来源：`useSessionTerminals`（ChatPage 单实例，实时 run events + 5s/20s 兜底对账 + 页面隐藏暂停 + `lastSyncedAtMs`）。
- **操作 API**：`sessionsClient.stopChildren(token, sessionId, { childSessionIds | all })` → `{ stopped, skipped[{reason}], failed[{error}] }`（`sessions.ts:534`）；`sessionTerminals.killTerminal(terminalId)`（已接线，`pendingKillIds` 提供进行中态）。
- **待复用 Props**（ChatPage 已组装）：`sessionTasks`、`sessionTerminals.{terminals,runningCount,loading,error,pendingKillIds,killTerminal,reload,lastSyncedAtMs}`、`openChildSessionInspector`、`handleStopChildSession`、`stoppingSubAgentIds`、`handleStopAllChildSessions`。

### 约束

- **禁止**在 `apps/` 直接 `fetch` 网关：新增请求必须走 `@openAwork/web-client`（v1 无新增请求）。
- 文件 ≤1500 行；>80 行渲染块或 >3 层嵌套必须拆组件；间距/颜色走 token（E · Nebula）；≥375px 响应式；loading/empty/error 三态 + focus ring 强制。
- 右栏 tab 栏是 40px 宽**垂直图标栏**（`overflowY: auto`），新增第 12 个 tab 不破坏布局。
- 当前工作区有多个 agent 并行改动 `apps/web` 与 gateway：本方案**不动网关、不触协议层**，改动集中在 `pages/chat-page/panels/**`（以新文件为主）+ `right-panel-tabs.tsx` 1 处登记。

## 方案设计

### 备选对比

| 备选 | 说明 | 取舍 |
| --- | --- | --- |
| A. 概览 tab 内加 section | 复用现有信息架构 | 概览已有多卡片，运行期查找成本高；不推荐 |
| B. 只做底部汇总条 | 复用 `TerminalCollapsedRail` 模式 | 空间不足以承载行级操作与 `task_id`；只适合做入口 |
| **C. 右栏新增「后台」tab（推荐）** | 统一列表 + 汇总 + 操作 | 新增 1 个 tab 成本低、可达性高；v2 再用汇总条做入口 |
| D. 子代理并入「代理」、命令并入「终端管理」 | 不加 tab | 「统一视图」目标落空 |

### v1（推荐，零网关改动）

**位置**：右栏新增 tab `background`（标题「后台任务」，描述「统一查看当前会话的子代理任务与后台命令，支持停止 / 终止。」）。

**面板结构**（自上而下）：

1. **汇总条**：`N 个子代理运行中 · M 个后台命令` + 「全部停止」（子代理，复用确认弹窗模式）+ 「同步于 Xs 前」（读 `lastSyncedAtMs`，实时性可信度自证）。
2. **子代理任务区**：排序 `running → pending → 最近终态`；每行：状态点 / 标题 / `@agent` / `task_id`（等宽、可复制）/ `会话 <short>` / 耗时（running 用 `now-startedAt`；pending 显示「排队 Xs」= `startedAt ? startedAt-createdAt : now-createdAt`）/ 操作：[打开子会话]（`openChildSessionInspector`）+ [停止]（`handleStopChildSession`，`stoppingSubAgentIds` 呈现「停止中」）。
3. **后台命令区**：每行：状态点 / `command`（单行省略，`title` 给全文）/ `cwd`（紧凑）/ `terminalId`（可复制）/ 运行时长 / 输出字节 / 操作：[查看]（切到「终端管理」tab 并选中该终端）+ [终止]（`killTerminal`，二次确认）。
4. **三态**：loading 骨架；empty「当前没有后台任务」+ 触发说明（模型派发后台子代理 / 后台命令时出现）；error 显示 `sessionTerminals.error` + 重试（`reload`）。

**交互约定**：停止与终止都是破坏性操作 → 逐行二次确认（对齐 `BatchStopSubAgentsControl` 的 `AppDialog` 模式）；`stopChildren` 的 `skipped/failed` 必须逐行反馈（toast + 行内错误态，禁止静默）；列表变化用 `aria-live="polite"` 播报；≤640px 折为单列卡片（操作按钮转为次级行）。

**明确不做（v1）**：不改网关 / 不加接口；不做跨会话全局后台管理；不做历史归档视图；卡片内联操作与底部汇总条留 v2。

### v2（可选，按需排期）

- 时间线卡片内联操作：`background_output` 卡加「取消任务」、后台终端卡加「终止」（预览组件已解析 `kill` 结果，补按钮即可）。
- 折叠态展示可复制的 `task_id`（子代理卡 / 左轨列表）。
- 底部汇总条（复用 rail 模式）：`N 个子代理 · M 个后台命令` → 点击打开本面板。
- 运行中角标（会话列表 / 输入框上方已有子代理计数，后台命令计数补齐）。

  sessionId?: string;
  agent?: string;
  command?: string;
  cwd?: string;
  startedAtMs: number;
  endedAtMs?: number;

  outputBytesTotal?: number;
  terminalKind?: 'foreground' | 'background' | 'tmux';
  errorMessage?: string;
}

export function buildBackgroundTaskRows(input: {

## 验证策略

1. **单测**（纯函数 + 组件）覆盖状态映射、排序、三态、确认弹窗与失败反馈；
2. **真实浏览器**（harness，参考 `notice-3viewports` / `scroll-finalize` 既有基建）覆盖布局与可达性；
3. **手工冒烟**：同一会话内先后触发一个后台子代理（`Agent run_in_background=true`）与一个后台命令（`run_bash_in_background`），验证：面板实时出现 → 逐行停止/终止生效 → 全停生效 → 断流时「同步于 Xs 前」推进。

## 风险与缓解

- **R-01 数据窗口性**：`recovery.tasks` 受 turn limit 影响（只含加载窗口内任务）→ 面板标注「当前会话加载范围」，不承诺全量；后续可加按需拉取（需新接口，属 v2）。
- **R-02 停止的部分失败**：`stopChildren` 返回 `skipped/failed` → 必须逐行可见；全停失败时保留确认弹窗结果摘要。
- **R-03 终端能力差异**：只有 `kind='foreground'` 可输入/清屏 → 面板只提供「终止」与「查看」，不提供清屏。
- **R-04 实时性口径**：run events 断流依赖兜底对账（5s/20s，页面隐藏暂停）→ 顶部显示同步时间，避免把旧状态当实时。
- **R-05 并行开发冲突**：仅新增文件 + `right-panel-tabs.tsx` / `chat-right-panel.tsx` 的小改；不触协议层与网关，冲突面最小。
- **R-06 端覆盖**：本次仅 Web / 桌面（`apps/desktop` 复用 web 页面）；`apps/mobile` 不复用该组件，移动端后台管理另立（非目标）。

## 非目标

跨会话全局后台管理；后台任务持久历史 / 审计视图；修改模型侧工具契约；team 端布局；移动端面板。
