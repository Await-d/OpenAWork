# 资源能力集成使用方案

## Task Overview

目标是为当前已经引入的 `packages/resources` 资源体系创建后续集成与使用方案，明确 Skill、Agent、MCP、Commands、Prompts、Team Templates、Channel Persona 等资源如何被后台、前端和运行时正确读取、管理、触发与隔离。

本方案承接用户约束：

- 参考 OpenCowork 的资源组织方式，但不能把所有文件混在一个通用资源列表。
- 简单工具如果 OpenAWork 已有，不重复完整集成。
- `souls` / `SOUL.md` 等资源属于通道个人角色或工作区模板，不能作为普通 Skill/Agent 展示。
- 管理界面需要支持上传、新增、删除、实时识别。
- 后续代码实施前必须再次按本方案拆分并等待明确确认。

## Current Analysis

当前代码已经建立了第一层资源目录：

| 层级 | 当前状态 | 说明 |
| --- | --- | --- |
| 资源包 | `packages/resources/resources/*` | 已按 builtin/reference 分离部分 agents、skills、commands、souls、prompts、extensions、mcps |
| 后台目录 | `GET /resources` | 返回完整目录，不在后端裁剪 feature 资源 |
| 用户上传 | `POST /resources/uploads`、`DELETE /resources/uploads/:id` | 上传后合并系统目录与用户目录并实时返回 |
| web-client | `packages/web-client/src/session/resources.ts` | 已解析 `visibility`、`feature`、`usageKind` |
| 前端管理 | `apps/web/src/pages/resources/*` | 已拆为主资源目录与功能专用资源两区 |

关键设计事实：

- 后台必须返回完整目录，不能把 `souls`、`agentTemplates`、`commands`、`prompts` 过滤掉；过滤只属于资源中心 UI。
- `visibility: catalog` 表示可进入主资源目录；`visibility: feature` 表示只由特定功能读取或在功能专用区展示。
- `souls` 应进入 `feature: channels / usageKind: channel-persona`。
- `agentTemplates` 应进入 `feature: team / usageKind: agent-template`。
- 参考命令与运行提示词只作为模板或运行时材料，不等于自动注册可执行 server action。
- Channels persona 已进入首个功能接入闭环：后台会把通道选择的 `souls`
  materialize 到 channel session metadata，模型轮次再从 metadata 注入
  `<channel-persona>` 动态系统提示。

## Solution Design

### 1. 资源用途路由

| Area | Visibility | Feature | Usage kind | 使用位置 |
| --- | --- | --- | --- | --- |
| `skills` | `catalog` | `skills` | `skill` | Skill 注册、Skill 管理、模型可用能力说明 |
| `agents` | `catalog` | `agents` | `agent` | Agent catalog、Team 成员选择、只读预览 |
| `mcps` | `catalog` | `mcps` | `mcp-server` | MCP 设置、server 状态、工具注入 |
| `extensions` | `catalog` | `extensions` | `extension-example` | Extension 示例与后续安装模板 |
| `souls` | `feature` | `channels` | `channel-persona` | Channels 通道个人角色设定 |
| `agentTemplates` | `feature` | `team` | `agent-template` | Team / workspace memory 模板 |
| `commands` | `feature` | `commands` | `command-definition` | 命令帮助、命令模板、白名单执行描述 |
| `prompts` | `feature` | `prompts` | `runtime-instruction` | 运行时提示词片段、上下文注入 |

### 2. 后台使用规则

后台保留完整目录面：

- `listResourceCatalog()` 是功能读取的完整真相源。
- `listResourceCenterCatalog()` 只允许用于“资源中心主目录”轻量查询或测试，不作为运行时功能读取入口。
- 用户上传资源必须经过 Zod 边界校验，并在后台根据 `area` 派生 `visibility / feature / usageKind`，不信任前端传入用途字段。
- 上传和删除返回合并后的完整 catalog，保证前端实时识别。

### 3. 前端使用规则

前端必须通过 `@openAwork/web-client` 读取资源：

- `apps/web` 不直接 `fetch('/resources')`。
- 资源中心默认展示 `visibility === 'catalog'`。
- 功能专用区展示 `visibility === 'feature'`。
- 上传面板允许选择所有 area，但上传后由后台决定归属；前端只根据返回结果刷新。
- 后续 Channels / Team 页面读取资源时，应调用同一个 `ResourcesClient` 或共享 hook，不复制资源解析逻辑。

### 4. 功能接入路线

第一轮接入优先级：

1. Channels Persona：把 `souls` 接到 channel 配置，支持每个 channel 选择内置/用户上传 persona。
2. Team Templates：把 `agentTemplates` 接到 Team / workspace memory 初始化入口。
3. Skill Catalog：把 `skills` 的 builtin/reference/user 三类展示与启停能力对齐现有 skill registry。
4. MCP Catalog：把 `mcps` 与现有 MCP 设置页合流，避免出现第二套 MCP 管理面。
5. Commands / Prompts：只做描述、模板和上下文材料；可执行动作仍走命令白名单。

### 5. 运行时触发与隔离规则

| Resource kind | 触发入口 | 运行时读取方式 | 隔离边界 |
| --- | --- | --- | --- |
| Skill | Skill registry / capability manifest | 通过已安装 skill registry 暴露，不从资源中心直接执行 | 用户安装态、启停态与 sandbox 权限隔离 |
| Agent | Agent catalog / Team member picker | 作为 persona / role definition 输入，不自动产生 tool 权限 | Agent 定义与 session/team snapshot 隔离 |
| MCP | MCP 设置页 / server runtime | 继续走原生 MCP runtime、server 状态与 flat tool naming | serverId、OAuth、permission 与 session visibility 隔离 |
| Command | 命令面板 / server command allowlist | 只作为描述和模板，执行必须命中 gateway allowlist | 命令白名单、session owner、workspace permission 隔离 |
| Prompt | runtime prompt snippet | 由具体功能按 `usageKind` 选择性注入 | 不进入主资源目录，不跨功能自动注入 |
| Soul | Channels / future persona picker | Channel session metadata → dynamic system prompt | 按 channel instance 与 user uploaded resource 隔离 |
| Agent template | Team / workspace init | 初始化 workspace/team memory 的模板材料 | workspace snapshot 隔离，不能混入普通 Agent catalog |

### 6. 管理界面方案

资源中心必须保持“目录管理”而不是“运行时执行器”：

- 主目录只展示 `visibility === 'catalog'` 的 Skill / Agent / MCP / Extension。
- 功能专用资源单独展示 `visibility === 'feature'` 的 Souls / Agent Templates /
  Commands / Prompts，并显示其 `feature` 与 `usageKind`。
- 上传、新增、删除后以前端收到的合并 catalog 为准刷新，不用页面重载。
- Channels、Team、MCP、Skill 等具体设置页可以复用同一个 `ResourcesClient`，
  但必须在各自页面按 `feature / usageKind` 过滤，不能把所有资源混在一起。
- 用户上传资源必须在后台按 `user_id + area` 隔离；前端不能自行声明 system/builtin 来源。

### 7. 不重复集成边界

以下能力只登记或补说明，不新增第二套执行器：

- 文件读写编辑、Glob/Grep、Bash、WebSearch/WebFetch。
- Plan、Task、AskUser、Goal、Memory、Cron。
- Image generation、desktop control、browser automation 基础动作。
- 已有 MCP flat naming 与 builtin MCP server。
