# 大文件差异：不截断数据 + 按需加载

## 问题（实测证据）

网关 `/recovery` 为性能做瘦身（`services/agent-gateway/src/routes/session-route-helpers.ts`）：

| 常量 | 值 | 影响 |
|---|---|---|
| `SLIM_STRING_MAX` | 8000 | 每个字符串叶子截断，追加 `…[truncated, N chars omitted]` |
| `SLIM_DIFF_MAX` | 3000 | `fileDiffs[].before/after` 截断 |
| `OUTPUT_HARD_CAP_BYTES` | 64KB | 单条 tool 输出硬顶 |

**这不只是「看不到全文」，而是 diff 会算错。**

实测记录（`audit_logs` id=29299）：

```
真实 before/after：15263 / 15286 字符
真实差异：+1 / -1
瘦身到 8000 后：+0 / -0      ← 完全看不到改动
```

近 40 条写入类工具输出中 **32 条**超过 8000 字符阈值 —— 也就是说绝大多数文件变更结果的 diff 都可能失真。

## 用户诉求

> 如果对于这个修改的文件太大，前端能否不做截断，但是加载的时候也不默认全部加载出来

即：**数据要完整可得，但不默认加载**（会话载荷可达数 MB，默认全量会拖垮主线程）。

## 已有能力（无需新增后端）

| 层 | 现状 |
|---|---|
| 存储 | `session_file_diffs` + 备份文件保存**完整** before/after |
| 接口 | `GET /sessions/:sessionId/file-changes?includeText=true` 返回完整文本，无截断 |
| 客户端 | `createSessionsClient(gatewayUrl).getFileChanges(token, sessionId, { includeText: true })` 已封装 |
| 认证态 | `gatewayUrl` / `token` 可从 `useAuthStore` 直接读取，无需 props 透传 |

## 方案

保留当前默认路径（快、不发请求、用存活前缀画部分 diff + 如实标注省略量），
新增**用户主动触发**的补全入口：

```
快照被截断 · 省略 1062 字符，以下仅对比已保留的前段内容
[ 加载完整内容（省略 1062 字符） ]      ← 点击才请求
```

点击后：
1. `getFileChanges({ includeText: true })` 拉完整 `fileDiffs`
2. 按路径匹配定位该文件（全等 → 归一化分隔符 → 路径段边界后缀；**歧义或无匹配时报错，不猜**）
3. 用完整 `before/after` 重算 diff，省略提示消失，`+N/-M` 更新为真实值

## 硬约束

- **绝不自动加载**：默认零额外请求，否则等于把瘦身优化废掉。
- **匹配必须保守**：`endsWith` 会让 `bar.ts` 命中 `foobar.ts`；必须按路径段边界匹配，歧义时明确报错而不是展示错的数据。
- **无 sessionId 时隐藏按钮**：不留死交互。
- **失败可见**：加载失败要显示原因并可重试，不能静默、不能一直转圈。
- **加载中禁用**：避免重复请求。

## 落点

| 文件 | 职责 |
|---|---|
| `previews/use-complete-file-snapshot.ts`（新增） | 按需取数 + 状态机 + 按路径缓存 |

| `previews/file-change-result-preview.tsx` | 按钮 + 四态渲染 |
| `display/*` / `io/tool-output-preview.tsx` / `ChatPageSections` | `sessionId` 可选透传 |

## 验收

- 单测：匹配的三种模式 + 歧义 + 无匹配；状态机四态。
- 类型检查 / Prettier / 既有 tool-call 测试全绿。
- 真实浏览器：按钮存在且**未自动触发**；375/768/1440 无横向溢出；深浅主题。
