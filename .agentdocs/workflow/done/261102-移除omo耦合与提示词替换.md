# 移除 omo 耦合与提示词替换方案

## 任务概述

把 OpenAWork 中所有 **omo** 相关使用（MCP 层 + 提示词层 + 协议层 + 渲染层）**替换为原生能力**，
并同步调整提示词文案与存量数据兼容策略。

关键立场：本方案是**替代（replace）而非纯删除（delete）**。凡是 omo 提供的可用能力，都必须先确认
存在原生替代物，再移除入口；凡是提示词里指向 omo 的文案，都必须改指原生能力，不能留下死指针。

范围分两批，可独立交付、独立回滚：

- **批次 A（解耦，低风险）**：`omo` adapter MCP 全量移除 + 提示词/文案替换 + 能力替代映射 + 前端渲染回落。
- **批次 B（协议收敛，需决策）**：`call_omo_agent` 向 `subagent` 收敛 + Claude Code `Agent` 呈报名重映射
  + 委派白名单语义重定义。

批次 B 含**权限语义变化**，必须经决策门 D1/D2 拍板后才可实施，不得与批次 A 混在同一提交。

## 方案设计

### 一、替代映射表（本方案的核心交付物）

移除任何一项前，先确认「替代物是谁」。尚未确认替代物的条目**不得移除**。

#### MCP 层

| omo 侧条目 | 替代物 | 依据 / 备注 |
| --- | --- | --- |
| `mcp__omo__ast_grep`（候选，不可执行） | 原生 `ast_grep_search` / `ast_grep_replace` | 两者均已在 `MODEL_VISIBLE_GATEWAY_TOOLS`（`tools/tool-definitions.ts:200-201`）→ 能力零损失 |
| `mcp__omo__context7`（候选，不可执行） | **不引入**，文档检索走 `webfetch` / `websearch` | `mcp/builtin-mcps.ts:16-19` 注释已写明「context7 在 OpenAWork 当前没有真实使用场景，先不引入」 |
| `mcp__omo__adapter_catalog` | **无替代**（纯诊断信息），删除 | 仅暴露候选清单与解析诊断 |
| omo native alias（codegraph / lsp / git_bash / grep_app / open_websearch） | 各自内置 server（**本来就是复用**，无需任何改造） | `omo/omo-tool-manifest.ts:173-190` + `virtual-omo-mcp.ts` 的 alias 去重逻辑 |
| `omo` server 本身 | 从系统内置 MCP 列表移除 | `system-catalog.ts:71` |

> 结论：MCP 层**不存在能力缺口**。ast-grep 有原生工具、context7 属未引入项、其余 5 项本就走原生 server。
> 这条判定是本批次 A 可以安全执行的前提，需在 T-01 复核确认。

### 三、批次划分与回滚边界

- **批次 A**：D5 实施 + 链路 A 摘除 + 链路 C/D 文案替换 + 前端渲染回落。**单一提交可回滚**。
- **批次 B**：D1/D2 实施 + 协议收敛 + 兼容重映射 + 三处集合统一 + 权限派生器合并。**必须独立提交**，
  且提交信息需明示「委派入口收敛 + 白名单语义变更」。

## Complexity Assessment

- 5+ atomic steps：T-01 ~ T-29 共 29 项 → **+2**
- 多个独立并行流：后端 adapter 摘除 / 协议收敛 / 提示词文案 / 前端渲染兼容 / 存量迁移 / 测试验收 → **+2**
- 涉及 3+ 模块：`services/agent-gateway`、`packages/resources`、`packages/agent-core`、`packages/shared-ui`、
  `apps/web` → **+1**
- 单步预计 >5 分钟：批次 B 的兼容重映射与白名单迁移 → **+1**
- 结果需持久化给他人复核 → **+1**
- OpenCode 环境可用：否 → 0
- **总分：+7**
- **选择模式：Full orchestration**
- **路由理由**：跨 5 个模块 + 含权限语义变更 + 需存量数据兼容策略 + 需真实手工验收（设置页 / chat / 团队会话），
  必须先固化替代映射与决策门，再分波次实施。
