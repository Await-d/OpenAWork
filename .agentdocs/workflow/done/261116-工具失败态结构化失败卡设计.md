# 工具失败态结构化失败卡 — 设计

## 背景与问题

工具调用失败后，界面上只有一个红色单行 pill（`.tool-call-error-summary`），
由 `extractErrorSummary`（`apps/web/src/components/chat/tool-call/shared/extract-error-summary.ts`）产出：

```ts
if (typeof output === 'string') {
  const firstLine = firstNonEmptyLine(output);
  if (firstLine) return clamp(firstLine);   // 只取第一行，再截 80 字符
}
```

三个叠加缺陷：

1. **多行错误块被压成一行**。agentignore 拒绝、工作区越界这类错误，正文是「结论 + 原因 + 建议」的多段文本，取第一行就只剩结论。
2. **再被截到 80 字符**，且样式是 `white-space: nowrap` + `text-overflow: ellipsis`，真正原因经常落在截断点之后。
3. **展开后仍是一整段无结构文本**，没有任何分段、字段标签或可复制入口。用户要自己从几百字里找"到底为什么失败"。

## 真实失败形态（来自本机 `audit_logs` 采样，25 条）

| # | 形态 | 真实样本 | 可结构化程度 |
|---|------|---------|-------------|
| 1 | 权限/忽略拦截（多段中文） | `Access denied: file "…/temp/x.ts" is protected by agentignore rules. 该类路径受 agentignore 保护(常见受保护模式:`.env` / …)…请勿重复尝试读取或写入;如需其中的值,请让用户显式提供…` | 高：可拆出 `原因 / 路径 / 建议` |
| 2 | 前置条件缺失（英文单句） | `You must read file "…/x.tsx" before editing it` | 高：可拆出 `原因 / 路径 / 下一步` |
| 3 | 工作区边界（中文单句） | `目标路径超出当前工作区范围：/tmp/x.mjs（当前工作区：/home/await/project/OpenAWork）` | 高：可拆出 `原因 / 目标路径 / 边界` |
| 4 | 系统错误 | `ENOENT: no such file or directory, stat '…'` | 中：可拆 `错误码 / 详情 / 路径` |
| 5 | bash 失败对象 | `{ command, cwd, exitCode: 1, output, truncated, terminalId }` | 高：**已有 `BashTerminalCard`**，不应走通用失败卡 |
| 6 | 业务态非错误 | `Question request … has been created. Ask the user to answer it…` | 低：属正常流程提示，不该显示为红色失败 |

形态 5 已由 bash 终端卡覆盖（`block-tool-call.tsx` 的 `hasBashOutput` 分支），
形态 6 是 `is_error = 1` 但语义不是失败——两者都**不属于本次失败卡范围**。

## 目标

把形态 1–4 渲染为**结构化失败卡**：

```
✗ 写入被拒绝 · agentignore 保护路径        ← 标题：类型 + 一句话结论
─────────────────────────────────────────
路径   .omo/ime-guard-apply.ts            ← 字段区：可复制、可换行
原因   该路径命中 agentignore 保护规则      ← 每条独立标签，不做整段塞
建议   改用不受保护的工作区路径；或让用户显式提供该文件的等价内容
─────────────────────────────────────────
[复制错误详情]  [查看原始输出]
```

## 设计约束

- **不得丢失原始文本**：卡片底部始终保留「原始输出」入口，任何正则未能命中的部分都必须原样可见（宁可少拆，不可丢信息）。
- **识别失败即回退**：解析器无法稳定拆分时，退回当前的「整段文本 + 可复制」形态，不得渲染空卡片。
- **不做语义猜测**：只按**已知前缀/结构**匹配（`Access denied:`、`You must read file`、`目标路径超出当前工作区范围：`、`ENOENT:` 等），不靠关键词模糊推断，避免把普通文本误判成结构化字段。
- **标题必须仍是一行**：折叠态只看标题；完整信息在展开体。
- **不新增依赖**，不引入 i18n 框架，文案直接中文硬编码（与同目录其它预览一致）。
- **纯函数解析 + 独立单测**：解析器放在 `shared/`，返回判别联合类型；组件只负责渲染。

## 落点

| 文件 | 职责 |
|------|------|
| `shared/tool-failure-view.ts`（新增） | 纯函数：`buildToolFailureView(output, isError)` → 判别联合 |
| `previews/tool-failure-preview.tsx`（新增） | 结构化失败卡渲染 + 原始输出兜底 |
| `io/tool-output-preview.tsx` | 失败态优先走失败卡（早于各业务预览） |
| `shared/extract-error-summary.ts` | 标题摘要改为取「结构化结论」而非首行前 80 字 |
| `css/` | 失败卡样式，复用 `--danger` token 与 4/8/12 间距阶梯 |

## 验收

- 单测：覆盖形态 1–4 的解析、无法识别时的回退、原文不丢失。
- harness：真实 Chromium 渲染四类失败 + 折叠/展开 + 浅深主题 × 375/768/1440。
- 回归：现有 `extract-error-summary` 测试与工具卡测试全绿。
