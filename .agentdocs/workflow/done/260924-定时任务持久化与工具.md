# 260924-定时任务持久化与 schedule_manage（域三）

## Task Overview

按四域方案（域三，方案 B）分两步：**B-1** 把纯内存的 cron 调度持久化（任务定义 +
执行历史 + 重启恢复 + 中断标记）；**B-2** 新增模型可见工具 `schedule_manage`
（list / add / update / remove / enable / disable / history），复用同一调度器实例。

## Current Analysis

- 现状：`cron/scheduler.ts` 的 `CronScheduler` 纯内存（`jobs` / `activeJobs` /
  `executions` ring），`cron/router.ts` 直接操作单例；网关重启任务与历史全丢。
- 执行链：`runCronAgentJob`（`cron/agent-handler.ts`）→ `runSessionInBackground`
  （`routes/stream-runtime.ts`）；cron 会话在权限模型中已有「写操作 ask、仅委派免审批」。
- 既有回归网：`__tests__/cron/*`（超时 / 重入 / 历史裁剪 / 重排 / handler）
  与 `__tests__/routes/cron-routes.test.ts`（真实内存 DB + 真实路由）。

## Solution Design

### B-1 持久化

- 新表：`cron_jobs`（`CronJobRecord` 全字段）+ `cron_job_executions`
  （执行历史，按任务保留 200 条）。
- 新模块 `cron/cron-store.ts`：`upsertCronJob` / `deleteCronJob` /
  `listCronJobsForRestore` / `getCronJobById` / `recordCronExecution`（upsert + 裁剪）/
  `listCronExecutionsForJob` / `markInterruptedCronExecutions` / `restoreCronJobsFromStore`。
- `CronScheduler` 增加**可选第 5 构造参数** `CronSchedulerPersistence`
  （`upsertJob` / `deleteJob` / `recordExecution`）与 `restoreJobs()`：
  add / update / remove / fire（fire_count 回写 + 执行开始/结束两次记录）落库；
  `restoreJobs` 只装载不回写。既有单测不传 persistence，零影响。
- `cron/router.ts`：单例调度器注入 persistence（store 实现）；
  **history 路由改读持久化历史**（重启后可查）。
- `index.ts`：`listen` 之后新增 boot 步骤 `gateway.cron-restore`——
  标记中断执行 + 装载任务定义。

### B-2 工具

- `schedule_manage`（list/add/update/remove/enable/disable/history）；
  `list`/`history` 只读免审批，变更类 ask（`scope=action:jobId|new`，`always=[action:*]`）。
- 归属校验：只操作 `user_id` 匹配的任务；跨用户 → 未找到。
- **cron 会话禁止管理定时任务**（自我复制 / 无人扩权）；team / channel 同样拒绝；
  可见性同源隐藏（与 MCP / 记忆 / 技能共用 helper）。
- 调度器按需**动态导入**（`await import('./router.js')`）：避免
  `tool-definitions → cron/router → agent-handler → stream-runtime → tool-definitions` 模块环。
- 审批预览：调度类型 + 表达式/间隔/触发时间 + 时区 + prompt 片段。

## 复查轮（2026-09-24，独立复审）

- **F3 [P2] 修**：`update` 可把任务静默改成**永不触发**（如 `schedule_kind: 'cron'` 但
  `schedule_expr` 为空、或 `kind=at` 无时间）——`scheduleJob` 直接 return 且无任何提示。
  修复：按「结果态」校验调度一致性，仅在调度字段 / `enabled:true` 被改动时触发
  （只改名不受影响）；补回归。
- **F4 [P3] 修**：`add` 接受过去的 `at`（永不触发）与极小 `every`（高频空转）。修复：
  `schedule_at` 必须为未来时间；`schedule_every >= 1000ms`；补回归。
- **F5 [P3] 修**：删除任务留下**孤儿执行历史**（`cron_job_executions` 无 job 外键、
  路由对已删任务 404 后不可达、也不再被裁剪）。修复：`deleteCronJob` 事务内级联删除
  历史；补回归（含 delete_after_run 场景说明：一次性任务删除后其历史一并清理）。
- **F10 [P2] 修**：审批预览只展示任务名 / 调度 / prompt，**未展示执行环境**——
  模型可用无害任务名掩护「扩大工作区（working_folder）/ 换执行身份（agent_id/model）/
  换投递目标」。修复：① 预览补齐 working_folder / session_id / agent / model / 投递；
  ② `working_folder` 增加「必须落在当前会话工作区内」校验（已绑定工作区的会话
  fail-closed；未绑定沿用平台既有绝对路径语义，与 bash workdir 一致）；补回归。
- **复审确认无问题**：执行期归属校验（`assertOwnedSession` / channel owner）、
