## 决策（D-02 细分）

| 编号 | 结论 |
| --- | --- |
| D-02a | **密度只作用于卡片视图**：控件仅在 `viewMode === 'cards'` 时渲染（时间轴是单列竖排，不受密度影响），避免出现点了没反应的死控件 |
| D-02b | **两档阈值**：舒适 = `minmax(290px, 1fr)` + `padding 14px` + 提示词 2 行（即原样式）；紧凑 = `minmax(230px, 1fr)` + `padding 11px 12px` + 卡片内距 8px + 提示词 1 行 + 倒计时 19px→16px + 底栏内距 10px→8px |
| D-02c | **持久化** `sessionStorage['openAwork.schedules.density']`（与 `viewMode` 同族，只影响本标签页）；只认白名单值，脏数据/存储不可用一律回落「舒适」 |
| D-02d | **密度是卡片视图自有 props**（`SchedulesCardGridProps extends SchedulesViewCommonProps`），不塞进公共契约 —— 公共契约的注释明确要求「两视图必须完全一致」，而密度天然只属于网格 |

## 实施

- `schedules-view-types.ts`：新增 `SchedulesDensity = 'comfortable' | 'compact'`（含「为什么不在公共 props 里」的说明）。
- `schedules-card-grid.tsx`：新增 `SchedulesCardGridProps`，网格根节点输出 `data-density={density}`（**不写内联样式**，换档全交给 CSS）。
- `SchedulesPage.tsx`：`density` state（`readStoredDensity` 初始化）、`switchDensity`、工具栏在排序下拉后追加 `role="group" aria-label="卡片密度"` 的两个按钮（复用 `.sch-switch` 样式，与视图切换视觉一致）。
- `schedules-card-grid.css`：追加 `[data-density='compact']` 的四条规则（默认档不需要规则）。

## 踩坑记录

1. **收紧 props 契约会打断所有既有渲染点**：`density` 设为必填后，`schedules-views.test.tsx` 里 5 处 `<SchedulesCardGrid {...commonProps()} />` 全部失去类型合法性 → 在测试里加 `cardProps()` 脚手架（`{ ...commonProps(), density: 'comfortable' }`）而不是把 prop 改可选。**规则：契约收紧时优先改调用点，不要偷偷放宽类型。**
2. **偏好写进 storage 会让用例互相串味**：切「紧凑」会写 `sessionStorage`，切「时间轴」会写视图偏好 —— 若 `afterEach` 不清，后续用例会在错误视角/密度下起跑。`SchedulesPage.test.tsx` 的 `afterEach` 已补 `window.sessionStorage.clear()`。
3. **spy 要打在 `Storage.prototype` 上**（`window.sessionStorage.getItem` 是继承方法），否则 `vi.spyOn` 拿不到。
