## Solution Design

### 数据与格式

1. **源**：新表 `plugin_sources`（id/name/repo/ref/enabled/created_at），条目 = GitHub 仓库（`owner/repo`）+ 可选 ref（默认 `main`）
2. **市场清单**：仓库根 `openawork-plugins.json`：
   ```json
   {
     "name": "示例插件集",
     "plugins": [
       { "name": "demo-echo", "path": "plugins/demo-echo", "description": "...", "version": "1.0.0", "author": "..." }
     ]
   }
   ```
   无清单时回退「仓库即单个插件」（根目录需有 entrypoint）
3. **市场条目 ID**：`<sourceId>/<pluginName>`；详情含 README（raw 拉取，截断）、repo 链接、ref、install 参数

### 下载与安装（安全）

- 仅接受 `owner/repo` 形态 + `https://api.github.com/repos/<repo>/zipball/<ref>`（与技能侧同构）
- 下载大小上限（复用技能侧常量语义）、fflate 解压、zip 根目录剥离
- 解压到 `<dataDir>/plugins/.staging-<rand>/` 的临时目录 → 定位子路径 → **`installPluginFromPath(tempDir, { force })`**（staging+rename+entrypoint 校验+id 消毒）→ 清理临时目录 → `refreshPluginsFromDisk()`（激活 + 热重载）
- 失败一律 400/502 结构化错误；zip 炸弹/超大包拒绝

### API（契约先行冻结）

```
GET    /plugins/market/sources                → { sources: [...] }
POST   /plugins/market/sources                { repo, ref?, name? } → { source }
DELETE /plugins/market/sources/:sourceId
GET    /plugins/market?query=                 → { entries: [...], sources: [...] }
GET    /plugins/market/:sourceId/:name        → { entry, readme?, repoUrl }
POST   /plugins/install/github                { repo, path?, ref?, force? } → { install, plugin }
```

### UI

- 新面板「插件市场」（`?plugin=market`）：搜索框 + 刷新 + 来源管理（折叠：列表/添加/移除）+ 条目列表（名称/描述/版本/来源徽章）
- 条目展开详情：描述、版本、仓库链接、README 摘要、「安装」按钮
- **信任确认（必须）**：首次点击「安装」→ 确认态（「将以网关权限执行任意代码，来源：<repo>，确认安装？」）→ 确认后调用 + 进度/结果
- 安装成功提示「可在『已安装插件』中管理」

- **不做 npm**：保持「GitHub 源」边界；npm 需运行时包管理器，收益低。
- **契约冻结**：Phase 1 路由签名在 T-06 完成后冻结，Phase 2 按冻结契约开发。
- **网络测试**：单测全部 mock fetch；真实 GitHub 拉取不进入 CI（可作为手动验收脚本留档）。
