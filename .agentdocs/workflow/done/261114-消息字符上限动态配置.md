# 消息字符上限动态配置

## 任务目标

将 message/displayMessage 的固定 32768 字符限制改为可在设置页配置、保存后立即生效的持久化限制。
用户已明确授权实施。

## 复杂度评估

- 5 个以上步骤 +2；可分工前后端 +2；涉及三个模块 +1；长步骤 +1。
- 合计 6 分，完整编排；实施按依赖串行交接，探索可并行。

## 方案

- 默认 32768，可配置 1024～200000（与现有队列/输入历史存储护栏对齐）。
- 全局配置采用独立 SQLite 单例表；登录可读，ADMIN_EMAIL 对应用户可写。
- 在请求校验时读取当前值，覆盖 message 与 displayMessage；保留内部结构 schema 的硬护栏。
- web-client 封装读写与响应校验；Web/桌面复用设置连接页，提供加载、错误、保存反馈。
- 输入框读取配置，超限提示并阻止发送，保留草稿；服务端始终为最终校验。
- 风险：多端旧配置、SSE URL 长度、附件追加文本、内部续跑校验及并发工作区。
