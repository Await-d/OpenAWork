# .agentdocs/workflow/260507-web-图片生成工作台实施.md

## Task Overview
在 Web 左侧导航新增一个专用“图片生成”页面，作为独立于聊天页的图片工作台，集中承载文生图、基于已有图片继续编辑、结果历史与产物联动能力。

## Current Analysis
- 当前图片生成/编辑能力主要内嵌在 `ChatPage` 的图片模式中。
- 左侧导航由 `components/layout/RailIcon.tsx` 与 `components/layout/NavRail.tsx` 定义，路由由 `App.tsx` 与 `routes/preloadable-route-modules.ts` 接入。
- 现有前端图片请求主链路已封装在 `pages/chat-page/use-chat-image-generation.ts`，后端仍以 `sessionId` 为核心上下文。
- 当前会话图片复用能力已存在：可从当前会话 content artifacts 选择参考图继续编辑。
- 后端当前边界仍是单参考图编辑，不包含 mask / 多图编辑；专用页面需显式沿用这个限制，不能静默扩 scope。

## Solution Design
推荐新增 `/images/:sessionId?` 专用页面，并在左侧导航增加“图片”入口。

当前确认的产品决策：采用“完全独立”的图片工作台 session 策略。图片页维护自己的 session 与图片历史，不直接复用普通聊天 session。

页面设计建议：
1. 顶部为图片模型与参数控制区，复用现有 `useChatImageGeneration` 与 `ChatImageGenerationControls`。
2. 中间为大尺寸提示词输入与操作区，支持：
   - 文生图
   - 基于已上传图片编辑
   - 基于当前图片工作台会话已有 artifact 继续编辑
3. 右侧或下方为结果区，展示：
   - 最新结果预览
   - 当前会话图片历史
   - 快速“继续编辑 / 打开产物工作区”动作
4. 页面底层继续使用 session + artifact 作为存储上下文，以复用现有图片接口与 artifact 生命周期；但该页面持有独立图片工作台 session，交互语义以“图片工作台”为中心，而不是聊天转录。

## Implementation Outcome
- 新增文件：`apps/web/src/pages/ImagesPage.tsx`（图片工作台页面容器）。
- 修改文件：`apps/web/src/routes/preloadable-route-modules.ts`（`images` 预加载模块）、`apps/web/src/App.tsx`（`/images/:sessionId?` 路由）、`apps/web/src/components/layout/RailIcon.tsx`（`Images` 导航项 + 图标 + 中文标签「图片」）。
- 修改文件：`services/agent-gateway/src/session-workspace-metadata.ts` 给 `sessionMetadataPatchSchema` 加白名单 `imageWorkbench: z.boolean().optional()`，否则 `metadata.imageWorkbench=true` 会被 strict schema 拒成 400。
- Session 策略：进入 `/images` 时若没有 `sessionId`，自动调用 `createSessionsClient(...).create(token, { title: '图片工作台', metadata: { imageWorkbench: true } })` 并 `navigate(..., { replace: true })` 到 `/images/<id>`；在同一会话内调整的参数/上传的参考图不会被「切会话弹回」影响（本轮先前修复的 `hasAppliedSavedImageDefaultsRef` 同样适用于本页）。
- 参考图规则：沿用后端现有「单参考图编辑」边界 —— UI 强制「会话历史选中」与「新上传文件」二选一；上传文件在提交时才通过既有 `/sessions/:id/artifacts/upload` 链路（`uploadChatAttachments`）持久化，失败会抛错并回显。
- 共享限制：图片生成插件未启用 / 未配置支持图片生成的模型时，按钮禁用并在 header 显示引导文案。
- 验证：`pnpm --filter @openAwork/web typecheck` OK；`pnpm --filter @openAwork/web test` 8 files / 307 tests 全过；`session-images-routes.test.ts` 8 tests 全过。
- 未做：重型组件渲染测试（apps/web 暂无 RTL 基础设施）、mask / 多图 / 批量变体（超出本次 scope，按文档 Notes 推迟）。

## Backend Schema Note
- `sessionMetadataPatchSchema` (`services/agent-gateway/src/session-workspace-metadata.ts`) 是 `.strict()`，新增任何会话级元字段都需要在该 schema 加白名单，否则 POST `/sessions` 创建会话会因 unknown key 返回 400。本次为图片工作台标记加了 `imageWorkbench: z.boolean().optional()`。修改后 agent-gateway 进程**需要重启或等待 watch 模式编译**才会生效。

## History Aggregation (跨会话画廊)
**用户需求**：图片工作台底部「会话历史」要展示**当前用户所有 imageWorkbench session** 中生成/上传的图片，不重复 chat session 的产物。每次「新建工作台」后历史仍可见。

**实现**：
- 后端：`services/agent-gateway/src/artifact-content-store.ts` 新增 `listImageWorkbenchArtifacts(userId, options)`，用 SQL `INNER JOIN sessions` + `json_extract(s.metadata_json, '$.imageWorkbench') = 1` 过滤；支持 `type` / `limit` 参数（默认 200，硬上限 500）。
- 后端路由：`services/agent-gateway/src/routes/artifacts.ts` 新增 `GET /image-workbench/artifacts?type=image&limit=200`，返回 `{ contentArtifacts: ArtifactRecord[] }`，与既有 `/sessions/:id/artifacts` 响应格式一致以便前端复用 `toImageEditReferenceArtifacts`。
- 前端：`apps/web/src/pages/ImagesPage.tsx` 内部 fetch 从 `/sessions/${routeSessionId}/artifacts` 切换到 `/image-workbench/artifacts?type=image&limit=200`，依赖列表移除 `routeSessionId`，新建工作台后通过 `setArtifactsRefreshKey` 主动刷新。
- 验证：`agent-gateway` typecheck OK，`session-images-routes.test.ts` 8/8 通过；`apps/web` typecheck OK，307/307 测试通过。
