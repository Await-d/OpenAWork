# 审批请求只读定位

## 目标与范围

新增 `permission_get({ session_id, request_id })`，使父代理与子会话可以读取同一用户拥有的审批请求详情；补齐审批通知中的父会话与查询指引。
查询覆盖 pending、deciding 及终态，严格只读，不批准、不续跑、不回收过期记录。

## Complexity Assessment

- 原子步骤：4 → 0 分。
- 独立并行实施流：无，注册与指引依赖查询契约 → 0 分。
- 系统：网关单一系统 → 0 分。
- 超过 5 分钟的步骤：有 → 1 分。
- 额外持久化审阅要求：无 → 0 分。
- OpenCode：未确认 → 0 分。
- 总分：1；模式：Lightweight。
- 理由：同一网关内的小型端到端工具能力，顺序实施；只读探索可并行。

## 设计与风险

- 按当前调用会话的 userId 校验目标会话所有权；不存在与越权使用相同结果。
- 仅返回审批所需的 rawInput、toolCallId、状态及裁决信息，不返回 requestData 等内部请求或认证上下文。
- 不复用仅支持 pending/approved/rejected 的 UI 映射器，以免丢失 deciding/consumed。
- 接齐模型定义、参数、沙箱、只读权限分类、折叠目录、团队与子会话可见性。
- 通知增加 parentSessionId 和查询示例；跨会话任务定位先核实最小安全方案。
- 工作区已有大量并行改动，逐处补丁保留其内容，不提交。
