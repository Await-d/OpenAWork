# 会话渲染性能优化

## 目标与授权

用户在性能审查后明确要求“修复优化”。优化 Web/Desktop 共用会话渲染；保留顺序、完整复制、展开操作、自动贴底及数学/引用语义。

## Complexity Assessment

- 5 项以上原子步骤：+2。
- 独立并行工作流：+2。
- 3 个以上模块（列表、工具预览、Markdown、流协议）：+1。
- 单步骤超过 5 分钟：+1。
- 持久化验证记录：+1。
- 总分：7；Full orchestration。
- 原因：按文件边界隔离实施，汇总后统一验证跨模块行为。

## 现状与风险

- 当前工作区有大量既有暂存/未暂存修改；以当前文件为基线增量修改，不回滚、不暂存、不提交。
- 虚拟布局每次流式尾部变化重建，测量 ref 不稳定。
- 工具对象/数组预览存在无预算全量序列化与挂载。
- Markdown 有全文规范化/分块扫描；文档级结构必须保持静态语义一致。
- 恢复/团队流及工具参数存在批处理前计算。
