# 260924-AI 自助管理扩展（四域）

## Task Overview

在 `mcp_manage_servers`（已交付）之后，按同一范式为四个域提供"审批下的 AI 自助管理"：
**技能安装/卸载/启停、定时任务、记忆、自定义 Agent / 团队模板**。本文档先出方案，待批准后
按域逐个实现（每域独立验收、独立归档）。

## 可复制的范式（MCP 工具已验证）

每个域的实现清单固定为 9 件（缺一不可）：

1. 零依赖工具名常量模块（供策略模块复用，避免重依赖）；
2. 管理模块（读-改-写 + 复用既有校验 schema + 敏感字段脱敏 + 会话守卫）；
3. agent-core `PERMISSION_CATEGORIES` 新增类别（默认 ask）；
4. `TOOL_TO_PERMISSION_CATEGORY` 映射 + 权限派生器（只读动作返回 null，变更动作
   `scope=action:target`、`always=[action:*]`）；
5. `MODEL_VISIBLE_GATEWAY_TOOLS` + `TOOL_WHITELIST` 登记（guard 测试强制分类）；
6. `tool-sandbox` 执行分支（parse → 守卫 → 执行 → 错误归一）；
7. 会话可见性（team / cron / channel 隐藏；clarify 自动排除）；
8. 能力目录提示（仅对可见会话注入一行使用指引）；
9. 测试四件套：模块单测（真实 schema/存储链路 + mock I/O）、沙箱接线（ask pending /
   免审批派发 / 守卫拒绝）、派生器与可见性增例、全量回归。

## 域一：记忆管理（建议第一个做）

- **现状**：`routes/memories.ts` 已有 list/create/get/update/delete + 抽取 + settings
  （9 个端点）；存储 `memories` / `memory_extraction_logs` 表；写入已有安全扫描
  `scanMemoryWriteContent`（`memory/memory-security-scanner.ts`）。**当前没有任何模型可见工具**。
- **工具**：`memory_manage`（`action: list | add | update | delete`，add/update 带
  `content / tags? / importance?`，delete 带 `memoryId`）。
- **权限**：新类别 `memory_manage`（ask）；`list` 只读免审批；写动作审批。
- **守卫**：team / cron / channel 会话拒绝（记忆是用户级长期上下文，不应被后台会话改写）。
- **生效性**：记忆注入按请求读取 ⇒ 写后即时生效。
- **风险/约束**：复用同一安全扫描；单条长度与数量上限沿用 memory settings；删除为破坏性操作，
  审批预览展示目标记忆摘要（截断）。
- **工作量**：约等于 MCP 工具的一半（无需连接池/探活）。

## 域二：技能安装 / 卸载 / 启停

- **现状**：`routes/skills.ts` 的 `/skills/install`（inline 安装逻辑约 120 行）、
  `/skills/installed/:skillId` DELETE、enable 端点、`/skills/search`、
  `/skills/registry-sources`（来源 CRUD + sync）；存储 `installed_skills` /
  `registry_sources`。模型侧只有 `skill`（加载）与 `skill_mcp`，无安装能力。
- **工具**：`skill_manage`（`action: search | install | uninstall | enable | disable`）。
- **前置重构（重要）**：把 `skills.ts` 的安装逻辑抽成共享服务模块（如
  `skill/skill-install-service.ts`），路由与工具同源调用——否则工具会复制一份安装逻辑，
  校验/权限授予漂移。
- **权限**：新类别 `skill_manage`（ask）；`search` 只读免审批；install/uninstall 审批。
- **守卫**：team / cron / channel 拒绝；安装只允许来自**已配置 registry 来源**的 skill
  （禁止工具直接接受任意 URL / 本地路径）。
- **审批预览必须展示**：skill id / 来源 / 权限清单（`permissions`）/ 是否内嵌 `mcp`
  （stdio 命令 = 任意命令执行，与 bash 同级）。
- **生效性**：`getEffectiveSkillsForSession` 读库 ⇒ 即时生效。

## 域三：定时任务（先定持久化）

- **现状**：`cron/router.ts` 的 `/cron/jobs` CRUD + enable/disable + history；
  **`CronScheduler` 是纯内存实现，重启即丢**（无 `cron_jobs` 表、无启动恢复）。
- **关键决策（2026-09-24 已拍板：方案 B）**：
  - ~~方案 A（快）：工具直接复用内存调度器，结果里明示"重启失效"。~~
  - **方案 B（已选）**：**先补持久化**（新表 `cron_jobs` + 启动恢复 + 执行历史落库）再做工具。
    理由：用户预期"每天跑"的任务不能重启即丢；工具必须建立在可靠存储上。
  - 实现顺序：B-1 持久化（表 + 仓储 + 启动恢复 + 历史）→ B-2 `schedule_manage` 工具。
- **工具**：`schedule_manage`（list / add / update / remove / enable / disable / history）。
- **权限**：新类别 `schedule_manage`（ask）；list/history 只读免审批；变更审批。
- **守卫**：**cron 会话禁止管理定时任务**（防自我复制 / 无人扩权）；team / channel 拒绝。
- **审批预览**：cron 表达式（或 at/every）+ 时区 + 完整 prompt 截断 + 投递目标 + agent/model。
- **风险**：无人会话执行是既有权限模型（写操作仍 ask、仅委派免审批）；工具只负责配置，
  执行链不再放宽。

## 域四：自定义 Agent / 团队模板

- **现状**：
  - 自定义 Agent：`routes/agents.ts` 的 `/agents` CRUD + reset；`agent/agent-catalog.ts`
    写入 `user_settings.agent_catalog` / `agent_preferences`；`systemPrompt` 有长度上限
    （`MODEL_REQUEST_SYSTEM_PROMPT_MAX_CHARS`）；内置 Agent 只允许改模型配置。
  - 团队：`/team/workspaces` CRUD（`team_workspaces` 表，含 roster 与能力绑定
    `mcpServerIds` / skills）；工作流模板在 `workflow_templates` 表（`/workflows/templates`）。
- **工具**：建议拆两个：
  - `agent_manage`（list / create / update / delete / reset，仅自定义 Agent）；
  - `team_workspace_manage`（list / create / update / delete，能力绑定必须走白名单校验）。
- **权限**：各新类别默认 ask；list 只读免审批。
- **守卫**：team / cron / channel 拒绝（团队会话不得改用户级 Agent / 团队配置）。
- **风险**：① Agent 的 `systemPrompt` = 改模型行为，需长度与内容校验（沿用路由 schema）；
  ② 团队能力绑定是授权面——绑定的 skills / mcp 必须逐个通过白名单校验（复用
  `mcp-server-authorization` / skill 有效性检查），禁止绑定未知来源。
- **工作量**：最大（两个工具 + 授权面校验）；建议最后做。

## Complexity Assessment

- Atomic steps：四域合计 28+ → +2
- Parallel streams：4 个独立域（但共享 `tool-definitions.ts` / `tool-sandbox.ts` /
  权限映射三个热点文件）→ 实际串行，0
- Modules/systems：agent-core + gateway（tools / permission / session / 四个业务域）→ +1
- Long step (>5 min)：每域核心模块 + 全量回归 → +1
- Persisted review artifacts：有 → +1
- OpenCode available：–1
- **Total score**：+4（单域 +4，批次 +5）
- **Chosen mode**：Full orchestration（Mode B 串行，一域一验收；每域独立归档）

## Notes

- 每域开工前复制本范式的 9 件清单作为该域 workflow 文档的验收表。
- 四域都不得放宽既有权限：deny 优先、显式 ask、team/cron/channel 守卫不可省。
- 敏感面：技能内嵌 MCP（命令执行）、定时任务（无人执行）、Agent prompt（行为改写）、
  团队能力绑定（授权面）——审批预览必须把"用户决策所需的最小事实"展示出来。
- 不做：Provider 裸 API Key、渠道凭据、权限规则放宽、permissionMode 自改。
