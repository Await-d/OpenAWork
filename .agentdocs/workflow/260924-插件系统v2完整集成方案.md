# 260924-插件系统v2完整集成方案

## Task Overview

将 OpenAWork 的插件系统从当前的 **V1 风格 hook bus**（`runtime/plugin-host.ts`，346 行，5 个 hook，`OPENAWORK_PLUGINS` 环境变量加载）升级为**对齐 opencode v2.0.15 的完整插件平台**：插件定义模型、域化 hook、Effect/Promise 双 API、生命周期管理、能力域（工具注册/事件/存储/配置变换）、声明式发现、热重载、安装与管理面。

- **参考基线**：`temp/opencode-v2.0.15`（tag `v2.0.15` / commit `6f3639d82e`）
- **本仓现状**：`services/agent-gateway/src/runtime/plugin-host.ts`（2026-09 引入，PR-D-Plugin，MVP 定位）
- **本文档定位**：分阶段可执行方案（T-XX 原子任务 + 验收契约 + Gate），**方案阶段，未开始编码**
- **当前状态**：待 Gate 0 决策

## Current Analysis

### 四、关键约束

1. **deny-first 权限不变量**：所有放行/免审批出口经 `gatePermissionDecision` 统一裁决；插件不得绕过沙箱。
2. **工具登记 6 处**：定义可见清单 / 沙箱 register / TOOL_WHITELIST / 权限分类 /（可选折叠）/（可选派生器）——漏登记会静默失效或被 guard 测试拦截。
3. **桌面 sidecar**：网关编译为 `bun build --compile` 二进制，插件加载路径需兼容编译后形态（`import()` 的可用性需验证）。
4. **无 fs 监听 / 无 npm 安装 / 无声明式配置文件**：这三项是热重载与安装面的前置新建项。
5. **移动端/桌面端复用 Web**：管理界面只需做 Web 一处。
6. **禁 `any`/`@ts-ignore`、ESM NodeNext、Zod 边界校验、中文提交**等仓库约定。

## Solution Design

### 总策略

**分层对齐、渐进交付、旧插件不破坏**。按参考库七层架构逐层映射，每阶段独立可交付、独立验收；现有 `OPENAWORK_PLUGINS` 插件在过渡期自动适配（V1 形状 shim），Phase 5 后提供迁移工具与文档。

**目标形态分层映射（本仓落点）**：

| 参考库层 | 本仓目标落点 | 形态适配 |
|---|---|---|
| SDK Effect/Promise | 新建 `packages/plugin-sdk/`（`@openAwork/plugin`） | Effect 4.0.0-rc.117 与参考库同源；Promise 兼容层保留 |
| Hook 域 | `services/agent-gateway/src/plugin/hooks.ts`（新建） | 首批对齐 `tool.*`/`session.*`/`permission.*`；`shell`/`aisdk` 按需 |
| 宿主 | `runtime/plugin-host.ts` 重构 → `plugin/host.ts` | 域 API 按本仓能力裁剪（无 TUI/persistentPty；RPC 见 Gate 决策） |
| 注册表 | `plugin/registry.ts`（新建，Effect Service） | 对齐 Slot/Activation/前缀 diff/revision/失败降级 |
| 发现/配置/监督 | `plugin/source.ts` + `plugin/module.ts` + `plugin/supervisor.ts` | 配置文件形态见 Gate D-6；目录 `.openawork/plugins/` |
| 内部插件 | `plugin/internal/*`（内置插件目录，按 Gate D-8 范围） | 先迁移 Provider 插件与工具组开关 |
| 管理面 | 网关路由 `/plugins/*` + Web `plugins-tab-content` 扩展 | 无 TUI，Web 即管理面；CLI 可选（Gate D-9） |

### 兼容与迁移策略

1. **旧插件 shim**：P1 提供 V1 形状适配器——`OPENAWORK_PLUGINS` 加载的 `(input, output)` hooks 自动包装为域化单事件注册；5 个旧 hook 名映射（`chat.message` → `session.prompt`、`chat.params` → `session.context`，等）。
2. **环境变量保留**：`OPENAWORK_PLUGINS` 在 P3 后作为配置文件的补充来源（合并语义），不废弃。
3. **失败隔离不变量**：过渡期保持"插件错误不中断主流程"；P1 起 `tool.execute.before` 是否允许抛错拒绝调用由 D-3 决定后按域对齐。
4. **双写窗口**：P3 起配置与 `user_settings` 同步写入，读取以配置文件优先。

| 风险 | 等级 | 缓解 |
|---|---|---|

| `tool.transform` 与工具折叠/权限链路冲突 | 🟡 中 | T-12 强制走 6 处登记 + guard 测试；折叠目录含插件工具 |
| 热重载引发开发期状态抖动 | 🟡 中 | digest 指纹去重 + 防抖；前缀 diff 只重建变更插件 |
| Effect 双 API 复杂度 | 🟡 中 | Promise 层是薄适配器；Effect 层类型独立测试 |
| 与既有"AI 自助管理四域"工作冲突 | 🟢 低 | 该批已收口；插件管理工具（如未来 `plugin_manage`）不在本方案范围 |

### 明确不做（本方案边界）

- **TUI 插件**：本仓无 TUI 形态，不移植。
- **RPC 跨进程插件**：无消费场景（D-7），列为 P5 后评估。
- **`shell.create.before` / `aisdk.*` / `session.http.*` / `ws.*` hook**：按需后补，首批不承诺。
- **`session.compaction` / `title` / `generate` 跳过模型调用的 hook**：涉及会话核心链路，独立评估后再做。
- **Provider 裸 API Key / 渠道凭据 / 权限规则放宽**：延续既有安全边界，永不做。
