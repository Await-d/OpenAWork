# 260923-渠道收尾清理第五批（QQ 入站图片 / relay enrich / 三处小修复）

## 任务概述

偿还四批交付后审计发现的全部可做剩余项（不需要产品决策、可验证的部分）：

1. **QQ 入站图片**：现为文本占位符，未产出 `images`（attachments 直映射 URL，与 Discord 同款）；
2. **relay 模式 enrich**：`ChannelRelay`（`wsUrl` 中转）不经过 HTTP 入站路由，Telegram/Slack 的 relay 形态图片不下载——补 enrich 接入；
3. **Discord `listGroups` 语义修复**：现返回 guild 列表而非消息容器（text channel）；
4. **飞书 `getGroupMessages` content 解析**：现返回原始 JSON 字符串（`{"text":"..."}`），解析为纯文本；
5. **weixin `pluginType` 一致性**：`weixin-official` → `weixin`（无其他引用，1 行）；
6. **`identity-mapping.ts` 未接线标记**：加模块注释说明预留状态（接线需产品设计，不代做）。

## 冻结契约

1. **QQ**（`inbound-parsers/qq.ts`）：新增 `readQQImageAttachments(event, maxCount)`（`content_type` 以 `image/` 开头 → `{ imageUrl: url, mediaType: content_type, ...(filename ? { fileName } : {}) }`；`url` 缺失跳过；上限 4）；C2C / Group / Channel 三个 parse 函数在返回时条件展开 `images`；`content` 逻辑（文本优先、占位符兜底）不变。
2. **relay**（`channel-relay.ts` + `manager.ts`）：`ChannelRelayOptions` 增可选 `enrich?: (message: ChannelMessage) => Promise<ChannelMessage>`；`handleMessage` 在 parse 通过且非 stale 后调用（**relay 内 try/catch 兜底**：失败 warn + 原样投递）；`manager.startRelay` 注入实现（查 `service.enrichInboundMessage` + `channelLogWarn` 兜底）。
3. **Discord**（`discord.ts`）：`listGroups` 改为「guilds → 各 guild 的 text channels（`type === 0`）」；guild 上限 10（防 N+1 失控）；单 guild 请求失败跳过；返回 `{ id, name }`（无 `memberCount`）。
4. **飞书**（`feishu-messaging.ts`）：`getFeishuGroupMessages` 的 `content` 经解析：JSON 且含 `text` → 提取纯文本；否则保留原字符串。
5. **weixin**（`weixin.ts`）：`pluginType = 'weixin'`。
6. **identity-mapping**（`identity-mapping.ts`）：加模块注释标记「预留能力，未接入生产链路；实际生效的是 `channel-member-acl.ts`；接线前需设计渠道用户 → 工作区用户映射流程」。
