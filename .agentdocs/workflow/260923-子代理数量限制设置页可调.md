# .agentdocs/workflow/260923-子代理数量限制设置页可调.md

## Task Overview

把子代理数量限制从网关硬编码常量改为**用户级、设置页可调**：

- 同时运行上限（`maxRunningPerRoot`，默认 4）
- 任务树累计上限（`maxTotalPerRoot`，默认 24）
- 嵌套深度上限（`maxNestingDepth`，默认 1）

保存后**立即生效**（判定发生在每次派发时，读 `user_settings`），无需重启网关；
已在运行的子代理不受影响；超限行为不变（拒绝派发 + 中文错误）。

## Current Analysis

- 现状：`tool-sandbox.ts` 三个硬编码常量（4 / 24 / 4），另有 `subagent_depth`
  用户级键（默认 1，护栏 8）只被 task handler 的深度校验使用。
- 两处深度口径重复且会叠加：`checkSubagentDepthAllowed`（`subagent_depth`）与
  `getTaskSessionLimitError` 的链深 4（`MAX_TASK_CHILD_SESSION_DEPTH`），
  用户把深度调高后仍会被链深 4 拦住，语义不一致。
- `subagentModelPolicy` 已有「user_settings + `/settings/providers` GET/PUT + 设置页
  子代理区域」的完整链路，可直接沿用。
- 约束：`apps/` 内禁止直接 fetch；设置页 UI 必须用 design token + 完整交互态。

## Solution Design

- **存储**：新键 `user_settings.subagent_limits`（JSON `{maxRunningPerRoot, maxTotalPerRoot, maxNestingDepth}`）。
  历史键 `subagent_depth` 保留为 `maxNestingDepth` 的回落来源（升级不重置用户已有设置）。
- **护栏**：并发 1–16、累计 1–200、深度 1–8；累计 < 并发 时自动抬升累计。
- **深度统一**：删除 `MAX_TASK_CHILD_SESSION_DEPTH` 链深校验，深度只由
  `maxNestingDepth` 一处控制（避免两条口径叠加）。
- **API**：`GET/PUT /settings/providers` 增加 `subagentLimits` 字段（与
  `subagentModelPolicy` 同区）。
- **前端**：设置页「连接」tab →「子代理」区域新增 `SubagentLimitsSection`（三个数字输入），
  随「保存默认值」一并提交。
