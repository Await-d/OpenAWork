# 260921-移动端图片查看器方案

## Task Overview

为 `apps/mobile`（Expo Router + React Native）**单独建立**一份「图片查看器」方案：让移动端能点击图片**放大查看**，并在同一条消息的多张图片之间**左右切换**，附带缩放/旋转/下载/关闭。

Web 端刚完成同名能力（`apps/web/src/components/chat/image/image-lightbox.tsx` + `ImageZoomTrigger` + `artifact-image-gallery.ts`），但该实现基于 DOM（`createPortal` / CSS / 键盘 / `getBoundingClientRect`），**RN 无法复用**，故单独立项。本方案以 Web 端的行为契约作为**对齐基线**，但实现路径完全自建。

## Current Analysis（现状核实，两路探索已确认）

1. **全应用唯一光栅图片渲染点**：`apps/mobile/src/components/chat-message-bubble.tsx:73` 的 `<Image source={{ uri: image.imageUrl }}>`，固定 180×180、`resizeMode="cover"`、**无任何点击处理**（外层 `Pressable` 只绑 `onLongPress` 唤起消息操作菜单）。
2. **「移动端看不到图」的根因**：`imageUrl` 唯一来源是本地文件 URI `file://…`（=`attachment.localUri`，在 `ChatScreen.tsx:721/807` 写入）。**从网关历史加载回来的消息只有 `artifactId`、没有 `imageUrl`** → 气泡里永远只显示占位符「图片已附加」。这与 Web 端用户抱怨（生成图看不到）属同一症状族。
3. **assistant 生成的图片产物根本不进气泡**，只进 `MobileAttachmentBar` 文字 chip；`app/artifacts.tsx` 的产物预览区只用 `<Ionicons>` 图标（第 171/181 行），**不加载图片内容**；`app/attachments.tsx` 同理。`app/image-workspace.tsx` / `image-params.tsx` / `image-progress.tsx` 只是生成表单/进度，无图片渲染。
4. **零手势/查看器依赖**：无 `react-native-gesture-handler`、`react-native-reanimated`、`expo-image`、`react-native-image-viewing`、`react-native-image-zoom-viewer`。且 `apps/mobile` **无 `babel.config.js`**（只有自定义 `metro.config.js`）→ 引入 `reanimated`/`gesture-handler` 需**新增 babel 插件 + 原生重建**（dev-client/EAS 重新出包）。
5. **图集数据前提已满足**：`collectInputImages()`（`src/chat/chat-message-content.ts:162-184`）递归收集 `input_image`，**保序、不去重、不限量**；`ChatMessageBubble` 按数组顺序逐张渲染。→ 「同一条消息 N 张图 → 图集切换」**无需改数据结构**，缺的只是点击入口 + 查看器 + 取数层。
6. **按 artifactId 取内容的客户端能力已存在但从未被调用**：`@openAwork/web-client` 的 `createArtifactsClient(gatewayUrl).get(token, artifactId)`（`GET /artifacts/:id`，图片含 base64；见 `packages/web-client/src/infra/artifacts.ts`）。移动端目前只用 `listForSession` / `uploadToSession` / `generateImage`。
7. **导航真相与文档冲突（须在方案内处理）**：实际活路由是 **Expo Router**（`app/_layout.tsx` 的 `<Stack>`；聊天页 = `app/chat/[sessionId].tsx` 渲染 `ChatScreen`）。而 `src/navigation/AppNavigator.tsx` **无任何 import（孤儿代码）**，`app/index.tsx` 是 `Redirect`。但 `apps/mobile/AGENTS.md` 仍声称「用手动屏幕状态机、新屏幕必须在 AppNavigator 注册」→ **文档与代码漂移**。另一个孤儿：`src/utils/artifact-platform-adapter.ts`（无引用）。
8. **测试基建（决定验证策略）**：`apps/mobile` 的 `test` = `vitest run --passWithNoTests`，现有 **7 个纯逻辑测试文件**（`chat-message-content.test.ts` / `chat-screen-state.test.ts` / `layout/*` / `auth` / `gateway-client` / `chat-message-actions`）。**无 `@testing-library/react-native`、无 jest** → **组件级渲染测试今日不可用**。故验证策略必须是：**把纯逻辑抽成可测模块（Vitest）** + **UI/手势走真机或 EAS preview 人工走查**（对齐仓库既有「真机验收」传统）。

## Solution Design

三层职责，与 Web 端的职责边界对齐（但 RN 全部自建）：

1. **取数层** `src/hooks/use-artifact-image-source.ts`：`artifactId` → 可显示图片来源。走 `createArtifactsClient(gatewayUrl).get(token, artifactId)` 取 base64，落盘为临时文件并返回 `file://`（或小图直接 `data:` URI）。带三态（loading/error/ready）、内存缓存、并发去重、abort、卸载保护。**这是「历史消息/产物图能显示」的前置依赖。**
2. **查看器** `src/components/image-viewer/ImageLightboxModal.tsx`（+ 子组件与纯逻辑模块）：图集索引（`items`/`index`/`onIndexChange`）、clamp、**边界禁用不循环**、`n / N` 进度、变换（缩放/旋转/重置）、滑动切换、工具栏、下载/保存、关闭（返回键/点空白/关闭按钮）。
3. **接入层**：`chat-message-bubble.tsx` 图片可点击 + `pressed` 态；`ChatScreen.tsx` 持有「当前消息 + 当前索引」的查看器状态并构造图集。

**设计铁律（源自 Web 契约的对齐结论）**：
- `count > 1` 才显示导航与进度；单图**不得**出现左右按钮；边界处继续切换 = **no-op 且回绕**（与轮播不同）。
- **切换图片时重置缩放/旋转，触发条件锚定「当前图片 src 变化」而非 index** —— RN 的 Pager 在数据刷新时 index 可能不变，照搬 index 会漏重置。
- 打开与关闭都重置变换（关闭清态，下次打开从 1× / 0° 起）；无有效项时**不渲染空壳**。
- 缩放区间 `0.25–5`、步长 `0.25`；旋转 `±90°` 步进；**「重置缩放」仅复位 scale，「重置全部」复位 rotation+scale**。
- **不要移植 Web 的「按渲染尺寸 4px 判定坍缩 + `data-intrinsic-size` CSS 兜底」**：RN `<Image>` 必须显式宽高，viewBox-only SVG 需走 `react-native-svg`。改为**数据层保证每条 item 带尺寸或 `aspectRatio`，缺失时给 48px 最小占位兜底**（对齐 Web 兜底值 `--spacing-12 = 48px`）。
- 禁止在 `apps/mobile` 内直接 `fetch()` 网关（根 `AGENTS.md` 硬规则），必须走 `@openAwork/web-client`。

## 能力对齐矩阵（RN ↔ Web 契约）

### A. 平台无关语义 —— 直接照搬，作为 RN 单元测试条目

| 组 | 契约 |
| --- | --- |
| 索引 | 图集优先于单图；受控 `index` 优先、内部 state 兜底；`clamp(0, count-1)`；`count=0 → 0`；**边界切换 = no-op，且不把相同索引回抛给受控调用点** |
| 导航 | 仅 `count > 1` 显示左右与进度；进度 = `当前+1 / 总数`（无 caption 也显示）；单图**不显示导航/进度**、且**不拦截**左右操作 |
| 变换 | rotation 90° 步进（可累计）、scale `0.25–5` 步长 `0.25`、默认 `1`；**「重置缩放」仅 scale，「重置全部」= rotation+scale** |
| 重置 | ① 打开 ②**当前图 `src` 变化**（不是 index）③ 关闭（清态，下次打开从 1×/0° 起） |
| 空态 | `!open` 或无有效项 → **不渲染空壳** |
| 文案 | `alt ?? caption ?? '图片预览'`；`fileName ?? 'image.png'` |
| 触发器 | `onOpen` / `label`（默认「放大查看图片」）/ `imageStyle` / `imageClassName` / `imageTitle` / `loading`；三态反馈（RN 映射 `pressed`/`focused`/`disabled`） |
| 图集构造 | 仅 `type === 'image'` 入集；**保序**；逐条解析 src，**不可解析者丢弃**；`content` 非字符串 → 丢弃不抛错；`data:` 仅接受 `data:image/` 前缀；裸 base64 拼 `data:<mime>;base64,…` 且 mime 须过 `image/*` 白名单（否则回退 `image/png`） |
| 四守卫 | 返回 `undefined`（调用方退化单图）：无选中 / 选中非图 / 无可渲染项 / **选中项不在过滤后条目里** |
| 映射 | `index` 是**过滤后**下标；`onIndexChange` 越界静默 no-op；选中态由父层持有（单一事实来源） |

> 可执行基线（Web 侧，RN 可直接引为对齐依据）：`apps/web/src/components/chat/image/image-lightbox.test.tsx`、`apps/web/src/components/common/display/ImageZoomTrigger.test.tsx`、`apps/web/src/pages/artifacts/views/artifact-image-gallery.test.ts`。

### B. 平台相关 → RN 等价替代

| Web 契约 | RN 替代 | 验收方式 |
| --- | --- | --- |
| 键盘 `←`/`→` 切图 | 横向滑动（`FlatList` `pagingEnabled` / `PanResponder`），边界不回绕 | 真机走查 + 纯逻辑单测 |
| `Esc` 关闭 | Android 硬件返回键 `BackHandler`；iOS 下滑/显式关闭按钮 | 真机走查 |
| 遮罩点击关闭 / `stopPropagation` | 背景 `Pressable` 关闭 + 独立 `Pressable` 层级阻断 | 真机走查 |
| `+`/`=`/`-`/`0`/`r` 快捷键、hover/focus | **工具栏必须完整暴露全部动作**（移动端无键盘）+ 捏合缩放 + 双击重置；`pressed`/`onFocus` 态 + `accessibilityRole` | 真机走查 |
| `<a download>` | `expo-file-system` 落盘 + `expo-sharing` / `MediaLibrary` | 真机走查（真实保存） |
| `ResizeObserver`/`IntersectionObserver`/`getBoundingClientRect` | `onLayout` + `Image.getSize`/`onLoad`；**无等价坍缩测量** | 纯逻辑单测（尺寸兜底） |
| `createPortal` + `position:fixed` | RN `Modal`（`transparent`/`animationType`）+ `StatusBar` 处理 | 真机走查 |
| `100vh/100vw`、`object-fit: contain`、CSS transform | `useWindowDimensions()`、`resizeMode="contain"`、`transform: [{rotate},{scale}]` | 真机走查 |
| `prefers-reduced-motion`、`aria-live` | `AccessibilityInfo.isReduceMotionEnabled()`、`announceForAccessibility` | 纯逻辑 + 真机走查 |

### C. RN 专属设计约束（必须写进实现）

- **C1（最重要）**：**不移植** Web 的「4px 渲染尺寸判定 + `data-intrinsic-size` CSS 兜底」。RN `<Image>` 必须显式宽高，viewBox-only SVG 需 `react-native-svg`。→ 数据层保证每条 item 带 `width/height` 或 `aspectRatio`，缺失时给 **48px 最小占位**兜底。
- **C2**：重置触发**锚定 src**（见 A 组「重置」），不要锚 index。
- **C3**：受控模式下要**主动阻止 Pager 的越界/回绕**，或在 clamp 后不派发 `onIndexChange`。

### 已知残留（诚实清单）

**代码层未闭合**
- iOS **无双击缩放**（有意取舍：`scrollResponderZoomTo` 矩形语义不可靠）；Android 有 1↔2 双击切换 → **两端交互不对称**
- Android 旋转态下捏合焦点存在**有界**锚点偏差（文件头已注明）
- 图集**未窗口化**：已修「离屏页被当前页缩放带动」，但离屏页仍挂载并解码整图（内存未优化；窗口化会破坏受控索引同步且无设备无法验证重挂载闪烁，故留作后续）
- 组件/渲染级测试基建缺失（无 `@testing-library/react-native`）→ **所有 UI 接线无自动化回归**
- 有意保留的 NITPICK：旋转累计 360° 仍判「已变换」；容差带内读数 `101%` 与 `deriveZoomed` 判定不一致

**仅缺真机验证**：goal1–4 的全部交互、D-3 落盘链路、Android 手势、iOS 嵌套滚动。

### 跨会话沉淀（durable lessons）

- `--fg-on-accent` **只能**用于 accent 实色填充之上；当作「深色遮罩上的文字色」或「纸张底色」会让暗色主题下内容不可见 —— 本仓库已多次回归（Web 端 4 处 + 移动端 2 处同类）。
- RN 0.83：`ScrollView` 的 `maximumZoomScale`/`minimumZoomScale`/`bouncesZoom`/`centerContent`/`zoomScale` **仅 iOS 生效**，Android 是**静默 no-op**（最危险的失败模式）。
- RN `<Image>` **必须显式宽高**，viewBox-only SVG 需 `react-native-svg`；**不可**移植 Web 的「按渲染尺寸判定坍缩 + CSS 兜底」。
- 沙箱 iframe / srcdoc **不继承宿主 CSS 变量** → 预览画布必须写字面色。
- `apps/mobile` **无 `babel.config.js`**、**无 RN 渲染测试库** → 引依赖需原生重建；可测性只能靠「纯逻辑下沉 + Vitest」。
- `apps/mobile` 的实际路由是 **Expo Router**（`app/_layout.tsx`）；`src/navigation/AppNavigator.tsx` 与 `src/utils/artifact-platform-adapter.ts` 是**孤儿代码**（2026-09-21 已更正 AGENTS.md）。
