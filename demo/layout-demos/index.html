Agents / Skills 页布局改版 · 方案对比

两个页面各 3 套方案，全部使用项目默认主题 E · Nebula Dark 的真实 token（逐值取自 apps/web/src/index.css），并覆盖现有页面的全部功能面（筛选、编辑、启停、恢复默认、移除、市场/本地/已安装三视图、注册源、安装进度）。选一套后我按它重构页面。

Agent 管理 · /agents

现为：Hero 卡 + 筛选卡 + 列表/编辑两列
A

控制台三栏

目录 · 编辑器 · 只读检视

统计内联进标题行，工具条只留一条；编辑分区成组，右栏常驻元信息与覆盖情况。

优点：信息密度高，改配置时不必来回滚动，覆盖情况一眼可见。 代价：需要 ≥1280px 才舒服；窄屏要退化为两栏／单栏。

表格 + 编辑抽屉

横向对比优先

全宽表格承载角色／模型／来源／状态／更新时间的横向对比，点行开抽屉编辑，列表上下文不丢。

优点：Agent 变多后仍然好扫；内置 Agent 的只读约束在抽屉里最直观。 代价：弱化了单条 Agent 的「说明」与提示词预览，需要在抽屉里展开。

卡片分组 + 全屏编辑

浏览清爽优先

按「自定义 / 内置」分组卡片陈列，点卡片进整页编辑视图（左侧分区导航 + 粘底操作条）。

优点：浏览态最易读，说明文案有位置；编辑页可放更多分组与帮助文案。 代价：编辑要跳视图；卡片密度低于列表，数量多时要靠分组与筛选兜。

技能 · /skills

现为：页头统计 + 分段 Tab + 卡片网格 / 整页详情
A

分类目录

分类轨 + 精选 + 全部

左侧分类轨与注册源简报常驻，右侧「精选 / 全部技能」双层陈列，已安装改为列表 + 注册源侧栏。

优点：市场有「目录感」，分类与注册源不再是两个孤立入口。 代价：精选区需要真实精选规则支撑，否则容易显得空。
打开方案 A
B

三栏内联详情

选择即查看，零跳转

左列表、中详情（概览／README／权限／更新日志）、右元信息与安装目标；安装与更新都在当前屏完成。

优点：最适合「装之前想看清楚」；详情不再整页替换，返回成本为零。 代价：三栏对宽度要求最高；详情信息量大时需要好的分区。
打开方案 B
C

网格 + 详情抽屉

保持浏览节奏

单条工具条承载全部筛选（含「仅看可安装」），卡片网格 + 右侧详情抽屉，安装进度以浮条呈现。

优点：浏览节奏不被打断；抽屉可关闭，网格立即变宽。 代价：抽屉里放不下完整 README，长文档仍需二次跳转。
打开方案 C

三套方案共同遵守的约束（选定后重构也按这个口径走）

  • 结构靠 --bg-* 层级 + 间距表达，描边只用 --border-subtle / --border-default；不再出现「大圆角卡片套卡片」与 22px 圆角外壳。
  • 语义色沿用 E · Nebula：靛青 = 强调/选中，琥珀 = 更新/警告，珊瑚 = 危险，靛蓝 = 信息/辅助。
  • 全部状态仍覆盖：加载中 / 无匹配 / 保存中 / 保存成功 / 错误 / 只读（内置 Agent）/ 依赖与权限提示。
  • 组件按职责拆文件，单文件不超过 1500 行；抽屉、列表、表单分别落到独立组件。
  • 重构时保留现有数据契约（createAgentsClient、useSkillsApi、useInstalledSkills）不变，只改视图层。
